# Урок 36. Юнит-тесты

## Цель
Понять, как автоматически проверять, что код работает, и не ломать старое при изменениях.

## Словарик новых слов
- **Тест** — маленькая программа, которая проверяет, что метод ведёт себя ожидаемо.
- **Юнит-тест** — тест одного «кирпичика» (метода/класса) в изоляции.
- **xUnit** — популярный фреймворк для тестов в .NET.
- **`[Fact]`** — пометка одиночного теста.
- **`[Theory]` / `[InlineData]`** — тест с несколькими наборами данных.
- **Assert** — «утверждение»: проверка ожидания.

## Теория «с нуля»

### Аналогия: проверка перед ремонтом
Прежде чем менять проводку, ты проверяешь, что лампочки горели. Тесты — то же самое: перед изменениями мы убеждаемся, что старое поведение не сломалось.

### Как выглядит тест
```csharp
public class Calculator
{
    public int Add(int a, int b) => a + b;
}
```

Тест:
```csharp
public class CalculatorTests
{
    [Fact]
    public void Add_TwoNumbers_ReturnsSum()
    {
        // Arrange (подготовка)
        var calc = new Calculator();

        // Act (действие)
        int result = calc.Add(2, 3);

        // Assert (проверка)
        Assert.Equal(5, result);
    }
}
```

Три части (AAA): Arrange → Act → Assert.

### Утверждения Assert
| Метод | Проверяет |
|---|---|
| `Assert.Equal(ожидаемо, фактически)` | равенство |
| `Assert.NotEqual(...)` | неравенство |
| `Assert.True(...)` / `Assert.False(...)` | истинность |
| `Assert.Null(...)` / `Assert.NotNull(...)` | null |
| `Assert.Throws<T>(() => ...)` | ожидаемое исключение |

### Theory с несколькими случаями
```csharp
[Theory]
[InlineData(1, 2, 3)]
[InlineData(-1, 1, 0)]
public void Add_ReturnsSum(int a, int b, int expected)
{
    Assert.Equal(expected, new Calculator().Add(a, b));
}
```

`[Theory]` — тест запускается для каждого набора `[InlineData]`.

### Зачем это нужно
- Страховка при правках (регрессии).
- Документация поведения.
- Можно рефакторить без страха.

### Запуск тестов
```bash
dotnet test
```

## Примеры

```csharp
public class PasswordValidator
{
    public static bool IsValid(string? password) =>
        password is not null && password.Length >= 8;
}

public class PasswordValidatorTests
{
    [Fact]
    public void IsValid_ShortPassword_ReturnsFalse()
    {
        Assert.False(PasswordValidator.IsValid("abc"));
    }

    [Fact]
    public void IsValid_LongPassword_ReturnsTrue()
    {
        Assert.True(PasswordValidator.IsValid("abcdefgh"));
    }
}
```

## Сделай сам (задачи с подсказками)

1. Напиши тест для `Add(2, 3)` через `Assert.Equal(5, ...)`.
   *Подсказка: AAA + `Assert.Equal`.*
2. Напиши `[Theory]` с `[InlineData]` для нескольких случаев.
   *Подсказка: параметры метода соответствуют значениям InlineData.*
3. Проверь, что `Divide` бросает `DivideByZeroException`.
   *Подсказка: `Assert.Throws<DivideByZeroException>(() => ...)`.*
4. Напиши тест на `IsValid(null)` → false.
   *Подсказка: `Assert.False(...)`.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Тест без `Assert` | ничего не проверяет | всегда завершай Assert-ом |
| Один тест со множеством актов | труднее локализовать | дроби на отдельные тесты |
| Тест зависит от `DateTime.Now` | плавает | передавай время параметром |
| Тест-«дубликат» | лишний прогон | один тест на сценарий |

## Тест — проверь себя

**Вопрос 1.** Что делает `Assert.Equal(5, result)`?
- A) Проверяет, что result равен 5.
- B) Присваивает result = 5.
- C) Выводит 5.

✅ **Верно: A.**
Почему: Assert.Equal — проверка равенства.
Почему неверны остальные:
- B — Это не присваивание.
- C — Это не вывод.

**Вопрос 2.** Что значит `[Fact]`?
- A) Тест всегда падает.
- B) Обычный одиночный тест.
- C) Тест с параметрами.

✅ **Верно: B.**
Почему: [Fact] — самый простой тест.
Почему неверны остальные:
- A — Он не обязан падать.
- C — Параметры — это [Theory].

**Вопрос 3.** Чем `[Theory]` отличается от `[Fact]`?
- A) Theory запускается с несколькими наборами данных ([InlineData]).
- B) Theory не имеет Assert.
- C) Theory запускается один раз.

✅ **Верно: A.**
Почему: Theory + InlineData — много случаев в одном тесте.
Почему неверны остальные:
- B — Assert там есть.
- C — Запускается несколько раз, по одному на InlineData.

**Вопрос 4.** Зачем тесты?
- A) Чтобы программа была длиннее.
- B) Чтобы ловить поломки при изменениях.
- C) Чтобы скрыть код.

✅ **Верно: B.**
Почему: тесты — страховка от регрессий.
Почему неверны остальные:
- A — Не для длины.
- C — Не для скрытия.

## Итог урока
- Юнит-тест проверяет один метод.
- AAA: Arrange → Act → Assert.
- `Assert.*` — утверждения.
- `[Fact]` — одиночный, `[Theory]` + `[InlineData]` — с данными.
- `dotnet test` — запуск.

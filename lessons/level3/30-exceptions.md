# Урок 30. Исключения и try/catch

## Цель
Понять, как программа сообщает об ошибках и как не дать ей «рухнуть».

## Словарик новых слов
- **Исключение (exception)** — специальный сигнал «что-то пошло не так». Программа «бросает» его в момент ошибки.
- **Бросить исключение** (`throw`) — создать и послать сигнал об ошибке.
- **Поймать исключение** (`catch`) — перехватить сигнал и среагировать.
- **try/catch/finally** — конструкция для «страховочной сетки».

## Теория «с нуля»

### Аналогия: будильник на кухне
Ты готовишь и вдруг — пожар (ошибка). Если ничего не делать, дом сгорит (программа упадёт). Но есть пожарная сигнализация: она «ловит» сигнал и вызывает МЧС. В коде роль сигнализации играет `try/catch`.

### Что происходит при ошибке без обработки
```csharp
int x = int.Parse("пять");   // ошибка: текст не превращается в число
Console.WriteLine(x);         // сюда не дойдём — программа упадёт
```
Программа «упадёт» с исключением. Чтобы это предотвратить — оборачиваем в try/catch.

### try/catch — страховочная сетка
```csharp
try
{
    int x = int.Parse("пять");
    Console.WriteLine(x);
}
catch (FormatException)
{
    Console.WriteLine("Это не число!");
}
```

- `try` — код, который может упасть.
- `catch (FormatException)` — что делать, если упал с ошибкой именно этого типа.
- После `catch` программа продолжает работу — не рушится.

### Какие бывают типы исключений
| Тип | Когда возникает |
|---|---|
| `FormatException` | неверный формат (например, «пять» в число) |
| `DivideByZeroException` | деление на ноль |
| `ArgumentNullException` | на входе null |
| `ArgumentOutOfRangeException` | значение вне диапазона |
| `FileNotFoundException` | файл не найден |
| `InvalidOperationException` | операция запрещена в текущем состоянии |

### finally — «выполнится в любом случае»
```csharp
try
{
    // рискованный код
}
catch (Exception ex)
{
    Console.WriteLine($"Ошибка: {ex.Message}");
}
finally
{
    Console.WriteLine("Это выполнится всегда — была ошибка или нет");
}
```

`finally` — для «уборки»: закрыть файл, освободить что-то.

### Один try — несколько catch
Можно ловить разные типы отдельно:
```csharp
try { ... }
catch (FormatException) { Console.WriteLine("Неверный формат"); }
catch (OverflowException) { Console.WriteLine("Слишком большое число"); }
```

## Примеры

```csharp
Console.Write("Введи число: ");
try
{
    int n = int.Parse(Console.ReadLine() ?? "");
    Console.WriteLine($"Квадрат: {n * n}");
}
catch (FormatException)
{
    Console.WriteLine("Это не число!");
}
```

## Сделай сам (задачи с подсказками)

1. Оберни `int.Parse(Console.ReadLine())` в try/catch и выведи «Это не число» при ошибке.
   *Подсказка: `catch (FormatException)`.*
2. Раздели два числа, обработай `DivideByZeroException`.
   *Подсказка: `catch (DivideByZeroException)`.*
3. Добавь `finally`, который пишет «операция завершена».
   *Подсказка: блок `finally { ... }` идёт после catch.*
4. Сделай два `catch`: для FormatException и для OverflowException.
   *Подсказка: разные блоки catch подряд.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| `catch { }` пустой | ошибка молча глотается | хотя бы логируй/выводи |
| `catch (Exception ex)` первым | перехватит всё, остальные бесполезны | конкретные типы — впереди |
| Ошибка вне try | не будет поймана | оборачивай именно рискованный код |
| `throw ex;` внутри catch | теряется стек вызовов | используй голый `throw;` |

## Тест — проверь себя

**Вопрос 1.** Что такое исключение?
- A) Число.
- B) Сигнал о том, что произошла ошибка.
- C) Имя метода.

✅ **Верно: B.**
Почему: исключение — механизм сообщения об ошибке.
Почему неверны остальные:
- A — Это не число.
- C — Это не имя метода.

**Вопрос 2.** Что делает `catch`?
- A) Бросает ошибку.
- B) Перехватывает ошибку и позволяет среагировать.
- C) Останавливает программу навсегда.

✅ **Верно: B.**
Почему: catch ловит исключение и выполняет свой код.
Почему неверны остальные:
- A — Бросает — это `throw`.
- C — После catch программа обычно продолжается.

**Вопрос 3.** Для чего нужен `finally`?
- A) Выполнить код, только если не было ошибки.
- B) Выполнить код всегда — была ошибка или нет.
- C) Завершить программу.

✅ **Верно: B.**
Почему: finally гарантированно выполняется.
Почему неверны остальные:
- A — Это было бы частью try без ошибки.
- C — finally не завершает программу.

**Вопрос 4.** Какой результат `int.Parse("пять")` без try/catch?
- A) Вернёт 5.
- B) Бросит исключение (FormatException), программа упадёт.
- C) Вернёт 0.

✅ **Верно: B.**
Почему: «пять» не превращается в число — возникает FormatException.
Почему неверны остальные:
- A — C# не понимает русские названия чисел «из коробки».
- C — 0 не вернётся, упадёт исключение.

## Итог урока
- Исключение — сигнал об ошибке, «бросается» при сбое.
- `try/catch` — перехват и реакция.
- `finally` — «уборка» в любом случае.
- Лови конкретные типы, не глотай ошибки молча.

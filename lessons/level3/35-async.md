# Урок 35. Асинхронность

## Цель
Понять, как не «замораживать» программу при долгих операциях (сеть, файлы, БД).

## Словарик новых слов
- **Асинхронность** — выполнение долгой операции, не блокируя остальное.
- **`Task`** — «обещание» будущего результата.
- **`async`** — пометка метода, что он асинхронный.
- **`await`** — «дождись результата, но не блокируй».
- **`CancellationToken`** — сигнал об отмене.

## Теория «с нуля»

### Аналогия: заказ пиццы
Ты заказал пиццу. Если ты будешь **блокирующе** ждать у телефона — ты не сможешь делать другие дела. Асинхронность — как «заказал и занимаешься своим делом; когда пицца готова — тебе позвонят». `await` — «жди звонка, но продолжай жить».

### Синхронно (блокирует)
```csharp
string data = File.ReadAllText("big.txt");   // пока читаем — программа «стоит»
```

### Асинхронно
```csharp
async Task<string> ReadFileAsync()
{
    string data = await File.ReadAllTextAsync("big.txt");
    return data;
}
```

- `async Task<string>` — метод асинхронный, вернёт строку.
- `await` — приостанавливает метод, НЕ блокируя поток.

### Что такое Task
`Task` — «обещание»: работа идёт, а результат будет. `Task<string>` — результат-строка.

### await и результат
```csharp
string result = await ReadFileAsync();
```
`await` «разворачивает» `Task<string>` в строку.

### async Task vs async void
- `async Task` — правильно (можно await, ошибки ловятся).
- `async void` — только для обработчиков событий; в остальных случаях опасно.

### Отмена (CancellationToken)
```csharp
async Task ProcessAsync(CancellationToken token)
{
    for (int i = 0; i < 100; i++)
    {
        token.ThrowIfCancellationRequested();   // проверить отмену
        await Task.Delay(100, token);
    }
}
```

### Сколько задач параллельно: Task.WhenAll
```csharp
Task<int> t1 = FetchAsync(1);
Task<int> t2 = FetchAsync(2);
int[] results = await Task.WhenAll(t1, t2);
```

## Примеры

```csharp
async Task<int> FetchAsync(int id)
{
    await Task.Delay(300);          // имитация задержки
    return id * 10;
}

// в Main:
int result = await FetchAsync(1);
Console.WriteLine(result);          // 10
```

## Сделай сам (задачи с подсказками)

1. Напиши `async Task<string> GreetAsync()`: `await Task.Delay(200);` затем возврат строки.
   *Подсказка: `return "Привет";` после await.*
2. Вызови его через `await` и выведи результат.
   *Подсказка: `var s = await GreetAsync(); Console.WriteLine(s);`*
3. Запусти два async-метода параллельно через `Task.WhenAll`.
   *Подсказка: `await Task.WhenAll(t1, t2)`.*
4. Добавь `CancellationToken` и отмену через `CancelAfter`.
   *Подсказка: `using var cts = new CancellationTokenSource(); cts.CancelAfter(100);`*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| `.Result`/`.Wait()` вместо await | блокировка, риск дедлока | `await` |
| `async void` не в обработчике | ошибки теряются | `async Task` |
| Метод `async` без `await` | предупреждение CS1998 | убери async или добавь await |
| Забыл `await` перед Task | получишь Task, а не результат | добавь `await` |

## Тест — проверь себя

**Вопрос 1.** Что делает `await`?
- A) Блокирует программу до результата.
- B) Приостанавливает метод, не блокируя поток, и дожидается результата.
- C) Ускоряет код.

✅ **Верно: B.**
Почему: await освобождает поток, ожидая результат.
Почему неверны остальные:
- A — Блокировка — это `.Result`/`.Wait()`.
- C — Это не про ускорение, а про неблокирование.

**Вопрос 2.** Что такое `Task<T>`?
- A) Число.
- B) «Обещание» будущего результата типа T.
- C) Массив.

✅ **Верно: B.**
Почему: Task — представление асинхронной работы.
Почему неверны остальные:
- A, C — Это не число и не массив.

**Вопрос 3.** Почему `async void` опасен вне обработчиков событий?
- A) Он медленнее.
- B) Ошибки в нём теряются, его нельзя await.
- C) Он всегда блокирует.

✅ **Верно: B.**
Почему: async void не возвращает Task, поэтому нельзя дождаться и перехватить ошибку.
Почему неверны остальные:
- A — Это не про скорость.
- C — Он не «всегда блокирует».

**Вопрос 4.** Что делает `Task.WhenAll(t1, t2)`?
- A) Ждёт первый завершившийся.
- B) Ждёт все переданные задачи.
- C) Отменяет задачи.

✅ **Верно: B.**
Почему: WhenAll ждёт завершения всех.
Почему неверны остальные:
- A — Первый завершившийся — это `Task.WhenAny`.
- C — Отмена — это CancellationToken.

## Итог урока
- Асинхронность — не блокировать поток при долгих операциях.
- `async Task` + `await` — правильный паттерн.
- `Task.WhenAll` — ждать несколько задач.
- `CancellationToken` — отмена.
- Не используй `.Result`/`async void` без нужды.

# Урок 31. Свои исключения

## Цель
Научиться бросать исключения самому и создавать свои типы ошибок.

## Словарик новых слов
- **throw** — оператор: «бросить исключение».
- **Своё исключение** — класс, унаследованный от `Exception`, для особой ошибки твоей программы.
- **Конструктор** — метод, вызываемый при создании объекта (из урока 22).

## Теория «с нуля»

### Аналогия: часовой
Ты — часовой на проходной. Если кто-то пытается войти без пропуска, ты не должен молча пропускать. Ты «бросаешь сигнал» — поднимаешь тревогу (исключение). А дежурный (catch) реагирует.

### Почему бросать самому
Метод должен сообщать, если входные данные плохие, а не молча делать неправильную работу:
```csharp
void SetAge(int age)
{
    if (age <= 0)
        throw new ArgumentOutOfRangeException(nameof(age), "Возраст должен быть положительным");

    // дальше работаем с корректным возрастом
}
```

`throw new ...` — создать исключение и бросить. После `throw` выполнение метода прекращается.

### Стандартные типы — когда какой
- `ArgumentException` — аргумент неверный в целом.
- `ArgumentNullException` — передан `null`.
- `ArgumentOutOfRangeException` — значение вне диапазона.
- `InvalidOperationException` — действие запрещено текущим состоянием.

### Своё исключение
Иногда стандартных мало — нужна «своя» ошибка со смыслом:
```csharp
class InvalidEmailException : Exception
{
    public string Email { get; }

    public InvalidEmailException(string email)
        : base($"Некорректный email: {email}")
    {
        Email = email;
    }
}
```

- Наследуемся от `Exception`.
- Имя заканчивается на `Exception`.
- В конструкторе передаём сообщение в базовый (`base`).
- Можно добавить свои свойства (например, `Email`).

Использование:
```csharp
void ValidateEmail(string email)
{
    if (!email.Contains('@'))
        throw new InvalidEmailException(email);
}
```

### Перехват своего исключения
```csharp
try
{
    ValidateEmail("не-почта");
}
catch (InvalidEmailException ex)
{
    Console.WriteLine(ex.Message);
}
```

## Примеры

```csharp
class AccountNotFound : Exception
{
    public AccountNotFound(int id) : base($"Счёт {id} не найден") { }
}

void FindAccount(int id)
{
    if (id != 42) throw new AccountNotFound(id);
}
```

## Сделай сам (задачи с подсказками)

1. Напиши метод `Withdraw`, бросающий `InvalidOperationException`, если денег не хватает.
   *Подсказка: `if (amount > balance) throw new InvalidOperationException("Недостаточно средств");`*
2. Создай своё исключение `InvalidPasswordException` и брось его при коротком пароле.
   *Подсказка: класс-наследник `Exception`, сообщение в `base`.*
3. Создай `InvalidEmailException` с полем `Email`. Поймай его через catch.
   *Подсказка: в catch обратись к `ex.Email`.*
4. Добавь `nameof` в сообщения стандартных исключений.
   *Подсказка: `throw new ArgumentException("...", nameof(age));`*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| `throw new Exception("...")` | слишком общий тип | используй конкретный или свой |
| Имя своего исключения без `Exception` | нарушает конвенцию | `...Exception` |
| `throw` после выполняющейся работы | «бросаем» слишком поздно | проверяй в начале метода |
| Забыл `nameof` в сообщении | сообщение без имени параметра | добавляй `nameof(...)` |

## Тест — проверь себя

**Вопрос 1.** Что делает оператор `throw`?
- A) Ловит ошибку.
- B) Бросает исключение, прекращая выполнение метода.
- C) Выводит ошибку на экран.

✅ **Верно: B.**
Почему: `throw` создаёт и «бросает» исключение.
Почему неверны остальные:
- A — Ловит — это `catch`.
- C — Вывод на экран — не задача throw.

**Вопрос 2.** Каким должно быть имя своего исключения?
- A) Любым.
- B) Заканчиваться на `Exception`.
- C) Начинаться с `I`.

✅ **Верно: B.**
Почему: это стандарт именования в .NET.
Почему неверны остальные:
- A — Есть конвенция.
- C — `I` — для интерфейсов.

**Вопрос 3.** От чего наследуется своё исключение?
- A) От `object`.
- B) От `Exception` (или его наследника).
- C) От `String`.

✅ **Верно: B.**
Почему: чтобы быть настоящим исключением и ловиться через catch.
Почему неверны остальные:
- A — `object` — корень всех, но не даёт поведения исключения.
- C — Не от строки.

**Вопрос 4.** Что произойдёт после `throw new InvalidPasswordException(...)` в методе?
- A) Метод продолжит выполняться.
- B) Выполнение метода прекратится, исключение уйдёт наверх.
- C) Программа выведет пароль.

✅ **Верно: B.**
Почему: `throw` немедленно останавливает метод.
Почему неверны остальные:
- A — Код после throw не выполнится.
- C — Вывод пароля не происходит.

## Итог урока
- `throw` — бросаем исключение, метод останавливается.
- Стандартные типы — под конкретные ситуации.
- Своё исключение = класс-наследник `Exception` с именем `...Exception`.
- Сообщение передаём в `base`.

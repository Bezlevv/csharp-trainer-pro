# Урок 46. Паттерны проектирования

## Цель
Познакомиться с проверенными решениями частых задач: Factory, Strategy, Observer.

## Словарик новых слов
- **Паттерн** — проверенное типовое решение повторяющейся задачи.
- **Factory (фабрика)** — централизованное создание объектов.
- **Strategy (стратегия)** — взаимозаменяемые алгоритмы за интерфейсом.
- **Observer (наблюдатель)** — один источник уведомляет многих подписчиков.

## Теория «с нуля»

### Factory: аналогия с заводом
Вместо того чтобы собирать машину каждый раз вручную, есть завод: передал параметры — получил готовый автомобиль. Фабрика скрывает детали создания.

```csharp
interface IPaymentProcessor { void Pay(decimal amount); }

class PaymentProcessorFactory
{
    public static IPaymentProcessor Create(string method) => method switch
    {
        "card" => new CreditCardProcessor(),
        "paypal" => new PayPalProcessor(),
        _ => throw new ArgumentException("Неизвестный способ")
    };
}
```

Использование:
```csharp
IPaymentProcessor p = PaymentProcessorFactory.Create("card");
p.Pay(1000);
```

### Strategy: аналогия с маршрутами
Можно добраться пешком, на автобусе, на такси. Способ «как добраться» взаимозаменяем. В коде — алгоритмы за одним интерфейсом.

```csharp
interface ITransport { void Go(string from, string to); }
class Walk : ITransport { public void Go(string f, string t) => Console.WriteLine($"Идём {f} → {t}"); }
class Bus : ITransport { public void Go(string f, string t) => Console.WriteLine($"Автобус {f} → {t}"); }
```

### Observer: аналогия с подпиской на блог
Блог публикует пост — все подписчики получают уведомление. Один источник, много подписчиков. В C# это события (event).

```csharp
class Blog
{
    public event EventHandler<string>? PostPublished;

    public void Publish(string title)
    {
        Console.WriteLine($"Опубликовано: {title}");
        PostPublished?.Invoke(this, title);
    }
}
```

Подписка:
```csharp
Blog blog = new Blog();
blog.PostPublished += (s, title) => Console.WriteLine($"Уведомление: {title}");
blog.Publish("SOLID простыми словами");
```

## Примеры

```csharp
// Factory: создание по выбору
var proc = PaymentProcessorFactory.Create("paypal");

// Strategy: подмена алгоритма
ITransport route = new Bus();
route.Go("A", "B");

// Observer: событие
blog.PostPublished += (s, t) => Mailer.Send(t);
```

## Сделай сам (задачи с подсказками)

1. Напиши `IPaymentProcessor` и фабрику для двух способов оплаты.
   *Подсказка: `Create(string method)` со switch.*
2. Сделай интерфейс `ITransport` и две стратегии (Walk, Bus).
   *Подсказка: метод `Go(from, to)`.*
3. Создай класс с событием и двух подписчиков.
   *Подсказка: `event EventHandler<string>?` + `+=`.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Создание объектов «размазано» по коду | сложно менять | фабрика |
| Огромный switch по способам в 10 местах | дублирование | фабрика инкапсулирует создание |
| «Наблюдатель» без события | плохо подписываться | использовать event |
| Забыл `?.Invoke` | NullReferenceException | `PostPublished?.Invoke(...)` |

## Тест — проверь себя

**Вопрос 1.** Что решает Factory?
- A) Централизованное создание объектов.
- B) Сортировку данных.
- C) Логирование.

✅ **Верно: A.**
Почему: фабрика создаёт объекты в одном месте.
Почему неверны остальные:
- B, C — Это другие задачи.

**Вопрос 2.** Что такое Strategy?
- A) Способ хранить данные.
- B) Взаозаменяемые алгоритмы за интерфейсом.
- C) Тип данных.

✅ **Верно: B.**
Почему: стратегия — сменяемое поведение через интерфейс.
Почему неверны остальные:
- A, C — Это не про хранение/типы.

**Вопрос 3.** Как в Observer источник уведомляет подписчиков?
- A) Через событие (`event`) и `?.Invoke`.
- B) Через прямое обращение к каждому.
- C) Через файл.

✅ **Верно: A.**
Почему: события — механизм Observer в C#.
Почему неверны остальные:
- B — Прямые ссылки — не паттерн Observer.
- C — Файлы тут ни при чём.

**Вопрос 4.** Зачем паттерны?
- A) Чтобы код был длиннее.
- B) Использовать проверенные решения и не изобретать велосипед.
- C) Чтобы запретить наследование.

✅ **Верно: B.**
Почему: паттерны — типовые проверенные решения.
Почему неверны остальные:
- A — Не для длины.
- C — Не про запреты.

## Итог урока

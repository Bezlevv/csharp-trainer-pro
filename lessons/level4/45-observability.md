# Урок 45. Наблюдаемость

## Цель
Понять, как «видеть» работающий сервис: логирование, метрики и трейсинг.

## Словарик новых слов
- **Наблюдаемость** — возможность понять, что происходит в системе.
- **Логи** — текстовые записи событий.
- **Метрики** — числа (сколько, как быстро).
- **Трейсинг** — цепочка «где потрачено время» по запросу.
- **`ILogger<T>`** — встроенное логирование в ASP.NET Core.

## Теория «с нуля»

### Аналогия: приборная панель пилота
Пилот видит: приборы (метрики), записи в журнале (логи), маршрут по точкам (трейсы). Без панели самолёт неуправляем. Так и сервис: без наблюдаемости сложно понять, почему он «лежит».

### Три столпа
| Столп | Вопрос | Инструмент |
|---|---|---|
| Логи | как произошло? | `ILogger<T>` |
| Метрики | сколько/как быстро? | `Meter`, `Counter` |
| Трейсы | где время? | `Activity` |

### Логирование через ILogger
```csharp
public class OrderService
{
    private readonly ILogger<OrderService> _logger;
    public OrderService(ILogger<OrderService> logger) => _logger = logger;

    public void Create(Order order)
    {
        _logger.LogInformation("Создание заказа {OrderId}", order.Id);
        // ...
    }
}
```

**Важно:** используй параметры `{OrderId}`, а не склейку строк:
```csharp
// плохо:
_logger.LogInformation($"Создан заказ {order.Id}");
// хорошо:
_logger.LogInformation("Создан заказ {OrderId}", order.Id);
```
Параметры позволяют фильтровать и агрегировать логи.

### Уровни логирования
`Trace`, `Debug`, `Information`, `Warning`, `Error`, `Critical` — от самых подробных до самых серьёзных.

### Метрики: Meter и Counter
```csharp
using System.Diagnostics.Metrics;

var meter = new Meter("Shop.Orders", "1.0");
var ordersCreated = meter.CreateCounter<int>("orders.created");
// при создании заказа:
ordersCreated.Add(1);
```

### Трейсинг: Activity
```csharp
var source = new ActivitySource("Shop.Orders");
using var activity = source.StartActivity("CreateOrder");
// внутри activity можно вешать теги
```

## Примеры

```csharp
try
{
    // ...
}
catch (Exception ex)
{
    _logger.LogError(ex, "Не удалось создать заказ {OrderId}", order.Id);
    throw;
}
```

## Сделай сам (задачи с подсказками)

1. Добавь `ILogger<T>` в класс и залогируй создание через `LogInformation` с параметром.
   *Подсказка: `LogInformation("... {Id}", id)`.*
2. Залогируй ошибку в catch через `LogError(ex, ...)`.
   *Подсказка: передавай исключение первым аргументом.*
3. Создай `Meter` и `Counter`, наращивай счётчик.
   *Подсказка: `meter.CreateCounter<int>("...")`.*
4. Почему параметры лучше склейки строк?
   *Подсказка: фильтрация и агрегация.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Склейка строк в логах | неструктурированно | параметры `{...}` |
| Пустой catch | тишина при ошибке | LogError |
| Логировать секреты | утечка | не логировать ключи/пароли |
| Всё через Information | шум | выбирать уровень |

## Тест — проверь себя

**Вопрос 1.** Что такое метрики?
- A) Текстовые записи.
- B) Числовые показатели (сколько, как быстро).
- C) Ошибки.

✅ **Верно: B.**
Почему: метрики — числа.
Почему неверны остальные:
- A — Это логи.
- C — Метрики не только про ошибки.

**Вопрос 2.** Зачем параметры `{OrderId}` в сообщении лога?
- A) Чтобы удобнее было склеивать.
- B) Чтобы можно было фильтровать и агрегировать логи по значению.
- C) Чтобы логи были короче.

✅ **Верно: B.**
Почему: параметры становятся отдельными полями.
Почему неверны остальные:
- A — Склейка — как раз то, чего избегаем.
- C — Не только про длину.

**Вопрос 3.** Как залогировать ошибку с исключением?
- A) `_logger.LogInformation("ошибка")`
- B) `_logger.LogError(ex, "не удалось {Id}", id)`
- C) `Console.WriteLine(ex)`

✅ **Верно: B.**
Почему: LogError принимает исключение и параметры.
Почему неверны остальные:
- A — Information не для ошибок.
- C — Console.WriteLine — не структурированное логирование.

**Вопрос 4.** Что из этого — НЕ столп наблюдаемости?
- A) Логи
- B) Метрики
- C) Имена переменных

✅ **Верно: C.**
Почему: имена переменных не относятся к наблюдаемости.
Почему неверны остальные:
- A, B — Логи, метрики (и трейсы) — столпы.

## Итог урока
- Наблюдаемость = логи + метрики + трейсы.
- `ILogger<T>` с параметрами — правильное логирование.
- `Meter`/`Counter` — метрики.
- `Activity` — трейсинг.
- Не логируй секреты, не глотай ошибки.

# Урок 41. SOLID · Open/Closed (OCP) и Лисков (LSP)

## Цель
Понять: новое поведение добавляем, не переписывая старое (OCP), а наследники не ломают обещания базового класса (LSP).

## Словарик новых слов
- **OCP (Open/Closed)** — классы открыты для расширения, но закрыты для изменения.
- **LSP (Liskov Substitution)** — наследник не должен ломать поведение базового класса.

## Теория «с нуля»

### OCP: аналогия с розеткой
Розетка «открыта» для подключения новых приборов, но «закрыта» для изменения самой розетки. Так и код: мы хотим **добавлять** новое (новый класс), не **переписывая** существующее.

### Плохо: switch по типу
```csharp
double Area(Shape s) => s switch
{
    Circle c => Math.PI * c.Radius * c.Radius,
    Rectangle r => r.Width * r.Height,
    // новая фигура → приходится ПРАВИТЬ этот метод
};
```
Каждая новая фигура заставляет менять этот метод — это «не закрыто для изменения».

### Хорошо: полиморфизм
```csharp
abstract class Shape { public abstract double Area(); }

class Circle : Shape
{
    public double Radius { get; }
    public Circle(double r) { Radius = r; }
    public override double Area() => Math.PI * Radius * Radius;
}
```
Новая фигура = **новый класс**, существующий код не трогаем. Это «открыто для расширения».

### LSP: наследник не должен ломать
Если базовый класс обещает «площадь всегда ≥ 0», наследник не должен возвращать −5. Если можно переопределение бросает исключение там, где базовый работает, — иерархия спроектирована плохо.

Пример плохого LSP:
```csharp
class Rectangle { public virtual double Area() => Width * Height; }
class Square : Rectangle
{
    public override double Area() => Side * Side; // может вести себя иначе
}
```

Пример опасного наследника:
```csharp
class Bird { public virtual void Fly() => ...; }
class Penguin : Bird { public override void Fly() => throw new Exception("не летает"); }
```
Использование «птицы» на пингвине сломается. Лучше не делать `Penguin` наследником летающего `Bird`.

## Сделай сам (задачи с подсказками)

1. Перепиши `switch` по фигурам через полиморфизм (абстрактный класс + override).
   *Подсказка: `abstract double Area();` + наследники.*
2. Добавь новую фигуру `Triangle` одним новым классом, не трогая остальной код.
   *Подсказка: просто создай `class Triangle : Shape`.*
3. Найди в коде место, где наследник «ломает» обещание, и исправь (разнеси классы).
   *Подсказка: если наследник бросает исключение в методе — пересмотри иерархию.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| switch по типу в 5 местах | правки в каждом месте | полиморфизм |
| Наследник бросает исключение в override | нарушение LSP | не наследовать там, где поведение несовместимо |
| Ожидание «базовых» гарантий от наследника | нарушено | гарантии должны сохраняться |
| Переписывать рабочий класс ради нового | не закрыт для изменения | добавлять новый класс |

## Тест — проверь себя

**Вопрос 1.** Что значит «открыто для расширения, закрыто для изменения» (OCP)?
- A) Новое добавляем новыми классами, старое не переписываем.
- B) Запрещено добавлять новое.
- C) Запрещено менять класс через наследование.

✅ **Верно: A.**
Почему: расширяем, не модифицируя существующий код.
Почему неверны остальные:
- B — Открыто для расширения — значит добавлять можно.
- C — Наследование как раз и есть способ расширения.

**Вопрос 2.** Почему switch по типу фигуры — плохо?
- A) Он работает медленно.
- B) Новая фигура требует править метод.
- C) Он не компилируется.

✅ **Верно: B.**
Почему: каждое добавление ломает/меняет существующий код.
Почему неверны остальные:
- A — Это не про скорость.
- C — Компилируется, но плохо масштабируется.

**Вопрос 3.** Что такое нарушение LSP?
- A) Наследник ведёт себя несовместимо с обещанием базового класса.
- B) Наследник переопределяет метод.
- C) Наследник добавляет новый метод.

✅ **Верно: A.**
Почему: LSP требует, чтобы наследник не ломал поведение родителя.
Почему неверны остальные:
- B, C — Переопределение/добавление сами по себе не нарушают LSP.

**Вопрос 4.** `Penguin : Bird` с `override Fly()` бросающим исключение — это:
- A) Отлично.
- B) Нарушение LSP.
- C) Нельзя объявить override.

✅ **Верно: B.**
Почему: «птица» для пингвина не летает — сломан контракт.
Почему неверны остальные:
- A — Это нарушение.
- C — Объявить можно, но это плохой дизайн.

## Итог урока
- OCP: **расширяем новыми классами, не правя старое**.
- LSP: **наследник не ломает обещания базового класса**.
- Полиморфизм — главный инструмент OCP.

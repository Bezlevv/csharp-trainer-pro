# Урок 44. Безопасность

## Цель
Понять основы защиты приложений: аутентификация, секреты и валидация входных данных.

## Словарик новых слов
- **Аутентификация** — «кто ты?» (проверка личности).
- **Авторизация** — «что тебе можно?» (права).
- **JWT** — подписанный токен-«пропуск» для API.
- **Секрет** — ключ/пароль, который нельзя раскрывать.
- **Валидация** — проверка входных данных.

## Теория «с нуля»

### Аналогия: пропуск на завод
Чтобы войти на завод, нужен **пропуск** (аутентификация — кто ты). Но даже с пропуском не все двери открыты: в серверную пускают только администраторов (авторизация — что тебе можно).

### Аутентификация vs авторизация
- Аутентификация отвечает на вопрос «кто?».
- Авторизация — на вопрос «что можно?».

### JWT — «пропуск с печатью»
JWT — это строка (токен), которую сервер выдаёт после успешного логина. Клиент шлёт её в каждом запросе, а сервер проверяет **подпись** и пускает.

```csharp
// клиент посылает заголовок:
// Authorization: Bearer <токен>
```

Проверка на сервере (настройка JWT в ASP.NET Core):
```csharp
builder.Services.AddAuthentication()
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidIssuer = "myapp",
            ValidAudience = "myapp",
            IssuerSigningKey = new SymmetricSecurityKey(keyBytes)
        };
    });
```

- `keyBytes` — секрет, полученный из переменной окружения.

### Секреты: где хранить
**Никогда** не пиши ключи и пароли в коде или в репозитории.

```csharp
string? key = Environment.GetEnvironmentVariable("JWT_SECRET");
```

Храни секреты в переменных окружения, в user-secrets или в Vault.

### Валидация входных данных
Не доверяй тому, что прислал клиент. Проверяй на границе API:
```csharp
if (string.IsNullOrWhiteSpace(request.Title) || request.Title.Length > 100)
    return Results.BadRequest("Некорректное название");
```

### Пароли
Храни только **хэш** пароля, а не сам пароль:
```csharp
var hasher = new PasswordHasher<object>();
string hash = hasher.HashPassword(null!, "секретный пароль");
```
Сравнение — через `VerifyHashedPassword`.

## Примеры

```csharp
// проверка секрета перед использованием
string? secret = Environment.GetEnvironmentVariable("JWT_SECRET");
if (secret is null) throw new InvalidOperationException("JWT_SECRET не задан");
```

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Секрет в коде/репо | утечка | env-переменные |
| Открытый эндпоинт без RequireAuthorization | доступ без проверки | защищать |
| Хранение пароля в открытом виде | кража паролей | хэшировать |
| Не проверять ввод | инъекции/мусор | валидация на границе |

## Тест — проверь себя

**Вопрос 1.** Аутентификация отвечает на вопрос:
- A) «Что тебе можно?»
- B) «Кто ты?»
- C) «Сколько времени?»

✅ **Верно: B.**
Почему: аутентификация — проверка личности.
Почему неверны остальные:
- A — Это авторизация.
- C — Это не связано.

**Вопрос 2.** Что такое JWT?
- A) Пароль.
- B) Подписанный токен-«пропуск».
- C) База данных.

✅ **Верно: B.**
Почему: JWT — токен с проверяемой подписью.
Почему неверны остальные:
- A — Это не пароль, а токен.
- C — Это не БД.

**Вопрос 3.** Где хранить секреты?
- A) В коде.
- B) В переменных окружения / безопасном хранилище.
- C) В readme.

✅ **Верно: B.**
Почему: секреты — вне кода и репозитория.
Почему неверны остальные:
- A, C — Код и readme попадают в git — это утечка.

**Вопрос 4.** Зачем валидировать входные данные?
- A) Чтобы код был длиннее.
- B) Чтобы не доверять клиенту и защититься от мусора/атак.
- C) Чтобы ускорить программу.

✅ **Верно: B.**
Почему: валидация — защита на границе.
Почему неверны остальные:
- A — Не для длины.
- C — Не для скорости.

## Итог урока
- Аутентификация — «кто», авторизация — «что можно».
- JWT — подписанный токен-пропуск.
- Секреты — только в окружении/хранилище, не в git.
- Пароли хранят как хэши.
- Валидируй ввод на границе API.

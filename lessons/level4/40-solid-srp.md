# Урок 40. SOLID · Single Responsibility (SRP)

## Цель
Понять первый и главный принцип качества кода: у каждого класса — одна работа.

## Словарик новых слов
- **SRP (Single Responsibility Principle)** — «принцип единой ответственности».
- **Ответственность** — причина, по которой класс может меняться.
- **God-класс** — класс, который делает слишком много всего.

## Теория «с нуля»

### Аналогия: рабочий-«всё-руки»
Представь рабочего, который и строит, и красит, и проводит электрику, и считает бюджет, и звонит клиентам. Если поменялись правила покраски — придётся трогать «всё», а заодно можно случайно сломать электрику. Лучше разделить: строитель, маляр, электрик, бухгалтер. У каждого — одна работа.

### Что такое «ответственность»
Если у класса есть **две причины для изменения** — значит, у него две ответственности. Например:
- «считает цену» (меняется при изменении правил ценообразования);
- «сохраняет в БД» (меняется при смене БД).

Это разные причины — класс стоит разделить.

### Плохо: God-класс
```csharp
class OrderProcessor
{
    public void Process(Order order)
    {
        // 1. проверить заказ
        // 2. посчитать итог
        // 3. сохранить в БД
        // 4. отправить email
    }
}
```

Всё в одном месте. Любое изменение — риск сломать остальное.

### Хорошо: раздельно
```csharp
class OrderValidator { public bool IsValid(Order o) => /* проверка */; }
class OrderCalculator { public decimal Calculate(Order o) => /* расчёт */; }
class OrderRepository { public void Save(Order o) => /* хранение */; }
class EmailNotifier { public void Send(Order o) => /* письмо */; }
```

У каждого класса — одна причина для изменения.

### Как понять, что SRP нарушен
Задай вопрос: «Какую одну работу делает этот класс?» Если ответ содержит «и ещё…» — пора разделять.

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Класс из 500 строк | много ответственностей | разбить |
| Метод делает 5 дел | трудно тестировать | декомпозиция на методы/классы |
| Ставить «всё» в один класс «для простоты» | дальше будет больно | сразу разделять по смыслу |
| Прятать логику в `Program` | главный класс-«свалка» | выносить в классы |

## Тест — проверь себя

**Вопрос 1.** Что означает SRP?
- A) У класса должна быть только одна причина для изменения.
- B) У класса должно быть много ответственностей.
- C) Класс должен быть маленьким по количеству строк.

✅ **Верно: A.**
Почему: единая ответственность = одна причина меняться.
Почему неверны остальные:
- B — Много ответственностей — это нарушение SRP.
- C — SRP не про количество строк, а про смысл.

**Вопрос 2.** Почему God-класс — это плохо?
- A) Он слишком быстрый.
- B) Изменение одной части рискует сломать другие.
- C) Он не может быть унаследован.

✅ **Верно: B.**
Почему: всё связано в одном месте, правки задевают друг друга.
Почему неверны остальные:
- A — Это не про скорость.
- C — Наследование тут ни при чём.

**Вопрос 3.** Класс делает «считает налог» и «сохраняет в БД». Это:
- A) Отлично, всё в одном.
- B) Нарушение SRP: две ответственности.
- C) Нельзя так делать вообще.

✅ **Верно: B.**
Почему: две разные причины для изменения → стоит разделить.
Почему неверны остальные:
- A — Это и есть нарушение.
- C — Так делают, но это плохая практика.

**Вопрос 4.** Какое правило помогает проверить SRP?
- A) «Сколько строк в классе?»
- B) «Какую одну работу делает класс?» (если ответ: «и ещё…» — разделяй)
- C) «Сколько методов в классе?»

✅ **Верно: B.**
Почему: вопрос про одну работу отражает суть принципа.
Почему неверны остальные:
- A, C — Строки и методы — не критерий SRP.

## Итог урока
- SRP: **одна ответственность = одна причина для изменения**.
- God-класс — анти-паттерн; дроби на классы по смыслу.
- Проверка: «Какую одну работу это делает?»

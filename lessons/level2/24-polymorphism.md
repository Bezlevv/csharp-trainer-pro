# Урок 24. Полиморфизм

## Цель
Понять, как один и тот же код может вести себя по-разному для разных наследников.

## Словарик новых слов
- **Полиморфизм** — (буквально «много форм») способность разных классов отвечать на одну и ту же команду по-своему.
- **Виртуальный метод** (`virtual`) — метод, который можно переопределить в наследнике.
- **Переопределение** (`override`) — замена поведения метода базового класса в наследнике.

## Теория «с нуля»

### Аналогия: один пульт, много устройств
У тебя есть пульт с кнопкой «Пуск». Для телевизора она включает экран, для микроволновки — нагрев, для кондиционера — обдув. Одна команда — но каждое устройство отвечает по-своему. Это полиморфизм.

### Проблема без полиморфизма
Хочется заставить всех животных «говорить», но по-разному:
```csharp
class Animal { public string Speak() => "..."; }
class Dog : Animal { public string Speak() => "Гав!"; }
class Cat : Animal { public string Speak() => "Мяу!"; }
```
Если держать собаку как `Animal`, вызовется `Speak` из `Animal` (потому что метод не виртуальный) — и мы получим «...», а не «Гав!».

### Решение: virtual + override
```csharp
class Animal
{
    public virtual string Speak() => "...";
}

class Dog : Animal
{
    public override string Speak() => "Гав!";
}

class Cat : Animal
{
    public override string Speak() => "Мяу!";
}
```

Теперь:
```csharp
Animal[] animals = { new Dog(), new Cat() };
foreach (Animal a in animals)
{
    Console.WriteLine(a.Speak());   // "Гав!" затем "Мяу!"
}
```

Ключевой момент: **во время выполнения** программа смотрит на фактический тип объекта (Dog, Cat) и вызывает именно его переопределённый метод. Это и есть полиморфизм.

### Для чего это нужно
- Новое животное = новый класс, а не правка всех `if`.
- Код работает с базовым типом `Animal`, а поведение у каждого своё.

### Абстрактные методы и классы
Если у базового класса нет смысла иметь реализацию, можно сделать метод `abstract` (без тела) и класс `abstract` (нельзя создавать объекты):
```csharp
abstract class Shape
{
    public abstract double Area();
}
class Circle : Shape
{
    public double Radius { get; }
    public Circle(double r) { Radius = r; }
    public override double Area() => Math.PI * Radius * Radius;
}
```

- `abstract class` — нельзя `new Shape()`, только наследники.
- `abstract` метод — обязан быть переопределён в наследниках.

   *Подсказка: `public override string Speak() => "Гав!";`*
2. Создай массив `Animal[]` со всеми тремя и выведи `Speak()` каждого через `foreach`.
   *Подсказка: foreach по `Animal` — вывод будет разный.*
3. Создай `abstract class Shape` с `abstract double Area()` и наследников `Circle`, `Rectangle`, `Triangle`.
   *Подсказка: в наследниках `override double Area()`.*
4. Вычисли сумму площадей всех фигур в массиве `Shape[]`.
   *Подсказка: `sum += s.Area();` в foreach.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| `override` без `virtual` в базовом | нечего переопределять — ошибка | добавь `virtual` в базовый класс |
| `virtual` без `override` в наследнике | метод скрывается, полиморфизм не работает | добавь `override` |
| `new Shape()` для abstract | нельзя создавать объекты абстрактного класса | создавай наследников |
| Забыл переопределить abstract-метод | класс останется абстрактным (или ошибка) | определи `override` |

## Тест — проверь себя

**Вопрос 1.** Что такое полиморфизм?
- A) Возможность одному коду вести себя по-разному для разных типов.
- B) Способ скрыть данные.
- C) Ускорение программы.

✅ **Верно: A.**
Почему: полиморфизм — «много форм» одного вызова.
Почему неверны остальные:
- B — Скрытие данных — это инкапсуляция.
- C — Полиморфизм не про скорость.

**Вопрос 2.** Зачем `virtual` в базовом классе?
- A) Чтобы его нельзя было наследовать.
- B) Чтобы разрешить переопределение метода в наследниках.
- C) Чтобы скрыть метод.

✅ **Верно: B.**
Почему: `virtual` «открывает» метод для переопределения.
Почему неверны остальные:
- A — Запрет наследования — это `sealed`.
- C — Скрытие — это `private`.

**Вопрос 3.** Что выведет код?
```csharp
class Animal { public virtual string Speak() => "..."; }
class Dog : Animal { public override string Speak() => "Гав!"; }
Animal a = new Dog();
Console.WriteLine(a.Speak());
```
- A) `...`
- B) `Гав!`
- C) Ошибку

✅ **Верно: B.**
Почему: несмотря на тип переменной Animal, фактический объект — Dog, и вызывается его `override`.
Почему неверны остальные:
- A — Так было бы без `virtual/override`.
- C — Ошибки нет.

**Вопрос 4.** Можно ли создать объект абстрактного класса (`new Shape()`)?
- A) Да.
- B) Нет — абстрактный класс нельзя инстанцировать.
- C) Да, но только один раз.

✅ **Верно: B.**
Почему: `abstract class` — только шаблон для наследников.
Почему неверны остальные:
- A — Нельзя.
- C — «Один раз» не имеет значения — нельзя вовсе.

## Итог урока
- **Полиморфизм** — один вызов, разное поведение.
- `virtual` + `override` — разрешение и замена поведения.
- Абстрактный класс/метод — шаблон без реализации, для наследников.

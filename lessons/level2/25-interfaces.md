# Урок 25. Интерфейсы

## Цель
Понять «договор на услуги» — интерфейс — и чем он отличается от наследования.

## Словарик новых слов
- **Интерфейс** — «договор»: список того, что объект обязано уметь. Без реализации — только «шапка».
- **Реализация интерфейса** — класс, который выполняет договор (пишет конкретный код методов).
- **Контракт** — то же, что договор: набор обязательств.

## Теория «с нуля»

### Аналогия: договор
Подрядчик и заказчик подписывают договор: «должен сделать ремонт до 1 числа». В договоре написано, **что** сделать, но не как именно — каждый подрядчик делает по-своему. Интерфейс — это такой договор для классов: «ты обязан уметь вот это» — но как именно, класс решает сам.

### Объявление интерфейса
```csharp
interface IPayable
{
    decimal CalculateAmount();
}
```
- Имя обычно начинается с `I` (от interface).
- Внутри — только «шапки» методов, без тела.

### Реализация классом
```csharp
class Salary : IPayable
{
    public decimal Monthly { get; set; }

    public decimal CalculateAmount() => Monthly;
}

class Contract : IPayable
{
    public decimal HourlyRate { get; set; }
    public int Hours { get; set; }

    public decimal CalculateAmount() => HourlyRate * Hours;
}
```

Оба класса «подписали договор»: они умеют `CalculateAmount()`, но считают по-разному.

### Зачем это нужно
Можно обращаться ко всем «платежам» единообразно:
```csharp
IPayable[] payments = { new Salary { Monthly = 50000m }, new Contract { HourlyRate = 1500m, Hours = 80 } };

foreach (IPayable p in payments)
{
    Console.WriteLine(p.CalculateAmount());
}
```

### Интерфейс против наследования
| Вопрос | Абстрактный класс | Интерфейс |
|---|---|---|
| Сколько можно «взять»? | один | несколько |
| Может содержать данные/поля? | да | нет (только контракты) |
| Когда выбирать? | есть общая логика + `IS-A` | нужен только контракт «умеет» `CAN-DO` |

Ключевая мысль: интерфейс описывает **что умеет** объект, а не **чем он является**.

### Несколько интерфейсов
Класс может реализовывать много интерфейсов:
```csharp
class Robot : IWorkable, IChargeable { ... }
```

## Сделай сам (задачи с подсказками)

1. Создай интерфейс `IPayable` с `CalculateAmount()` и две реализации (Salary, Contract).
   *Подсказка: имя интерфейса начинается с `I`.*
2. Создай `ILoggable` с методом `Log(string message)` и класс `ConsoleLogger : ILoggable`.
   *Подсказка: `public void Log(string message) => Console.WriteLine(message);`*
3. Создай интерфейс `IShape` с `Area()` и реализуй его в `Circle` и `Square`.
   *Подсказка: `class Circle : IShape { ... }`*
4. Покажи, что массив типа `IShape[]` может содержать и круг, и квадрат.
   *Подсказка: `IShape[] shapes = { new Circle(...), new Square(...) };`*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Метод интерфейса с телом | в интерфейсе нет тела | только «шапка» |
| Класс не реализовал все методы интерфейса | компилятор потребует | реализуй все методы |
| Интерфейс с данными/полями | интерфейсы не хранят состояние | не используй поля |
| «Реализация» с другим именем метода | должно совпадать с объявлением | точное совпадение имени/типов |

## Тест — проверь себя

**Вопрос 1.** Что такое интерфейс?
- A) Готовый класс с логикой.
- B) «Договор»: список методов, которые класс обязан реализовать.
- C) Переменная.

✅ **Верно: B.**
Почему: интерфейс задаёт контракт без реализации.
Почему неверны остальные:
- A — Готовый класс — это класс, не интерфейс.
- C — Это не переменная.

**Вопрос 2.** Сколько интерфейсов может реализовывать класс?
- A) Только один.
- B) Сколько угодно.
- C) Ни одного.

✅ **Верно: B.**
Почему: множественная реализация интерфейсов разрешена.
Почему неверны остальные:
- A — Один — это ограничение для классов (базовый класс один).
- C — Тогда зачем они нужны.

**Вопрос 3.** В чём главное отличие интерфейса от абстрактного класса?
- A) Интерфейс — только контракт (без данных и реализации); абстрактный класс может иметь реализацию и поля.
- B) Они полностью одинаковы.
- C) Абстрактный класс нельзя наследовать.

✅ **Верно: A.**
Почему: интерфейс — «что умеет», абстрактный класс может дать общую логику.
Почему неверны остальные:
- B — Есть различия.
- C — Абстрактный класс как раз создаётся для наследования.

**Вопрос 4.** Что обязан сделать класс, реализующий `IPayable`?
- A) Ничего.
- B) Реализовать все методы интерфейса (здесь — `CalculateAmount`).
- C) Создать объект интерфейса.

✅ **Верно: B.**
Почему: это и есть «выполнение договора».
Почему неверны остальные:
- A — Иначе компилятор выдаст ошибку.
- C — Объекты интерфейсов не создаются — интерфейс не класс.

## Итог урока
- **Интерфейс** — договор о возможностях (список методов, имя с `I`).
- Класс **реализует** интерфейс, выполняя все его методы.
- Интерфейсов может быть много; это про «умеет», а не «является».

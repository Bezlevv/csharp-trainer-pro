# Урок 28. Null-безопасность

## Цель
Понять, что такое `null`, почему обращение к нему ломает программу, и как безопасно с ним работать.

## Словарик новых слов
- **`null`** — «ничего», отсутствие ссылки. Переменная ссылочного типа может не указывать ни на что.
- **`NullReferenceException`** — ошибка: попытались использовать `null` как объект.
- **Nullable `?`** — пометка «может быть null».
- **`??`** — «если null, возьми что-то другое».
- **`?.`** — «если не null, обратись к члену».

## Теория «с нуля»

### Аналогия: пустая коробка
Представь коробку без содержимого (`null`). Если ты попробуешь взять из неё предмет (`box.Length`) — ничего нет, и программа упадёт. `null` — это «коробка с надписью: внутри ничего нет».

### Что такое NullReferenceException
```csharp
string s = null;
Console.WriteLine(s.Length);   // NullReferenceException
```
`s` — null, а мы просим `Length`. Это как открыть пустую коробку и требовать «достань предмет».

### Как предотвратить: проверка
```csharp
if (s != null)
{
    Console.WriteLine(s.Length);
}
```

### Оператор `??` — «если null, то…»
```csharp
string name = Console.ReadLine();      // может быть null
string safe = name ?? "Гость";        // если name == null → "Гость"
```

### Оператор `?.` — «если не null, обращайся»
```csharp
int? length = s?.Length;   // если s == null → length = null (без падения)
```

### Пометка nullable `?`
В современном C# мы «говорим» компилятору, может ли быть null:
```csharp
string? maybe = null;    // может быть null
string required = "текст"; // не должен быть null
```
Компилятор предупредит, если ты разыменуешь `maybe` без проверки.

### Чего не делать
- Не «глотать» NullReferenceException надеждой, что не случится.
- Проверяй входные данные (особенно извне: консоль, файлы, сеть).

## Примеры

```csharp
// Безопасное чтение
string? input = Console.ReadLine();
Console.WriteLine(input?.Trim() ?? "(пусто)");
```

## Сделай сам (задачи с подсказками)

1. Создай `string s = null;` и попробуй `s.Length` — запиши тип ошибки.
   *Подсказка: это NullReferenceException.*
2. Исправь это через `if (s != null)`.
   *Подсказка: проверка перед использованием.*
3. Используй `??` для значения по умолчанию.
   *Подсказка: `string x = s ?? "по умолчанию";`*
4. Используй `?.` и сравни результат с null.
   *Подсказка: `int? len = s?.Length;`*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| `s.Length` при s == null | падение | проверь или используй `?.` |
| Пометить `string` как nullable, а потом не проверять | компилятор предупредит | проверяй |
| Использовать `??` на null-объекте, не думая о смысле | иногда маскирует ошибку | выбирай осознанно |

## Тест — проверь себя

**Вопрос 1.** Что такое `null`?
- A) Ноль.
- B) Отсутствие ссылки («ничего»).
- C) Пустая строка.

✅ **Верно: B.**
Почему: null — отсутствие объекта, а не 0 и не "".
Почему неверны остальные:
- A — 0 — это число.
- C — "" — пустая, но *существующая* строка.

**Вопрос 2.** Что будет при `string s = null; Console.WriteLine(s.Length);`?
- A) Выведет 0.
- B) NullReferenceException.
- C) Выведет «null».

✅ **Верно: B.**
Почему: обращение к члену null-объекта падает.
Почему неверны остальные:
- A, C — Программа упадёт до вывода.

**Вопрос 3.** Что вернёт `s?.Length`, если `s == null`?
- A) 0.
- B) null.
- C) Ошибку.

✅ **Верно: B.**
Почему: `?.` безопасно возвращает null, не падая.
Почему неверны остальные:
- A — Не 0.
- C — Ошибки нет.

**Вопрос 4.** Что делает `string name = input ?? "Гость";`?
- A) Всегда присваивает «Гость».
- B) Если input == null, присваивает «Гость»; иначе — значение input.
- C) Бросает ошибку.

✅ **Верно: B.**
Почему: `??` — «если null, возьми правую часть».
Почему неверны остальные:
- A — Не «всегда».
- C — Ошибки нет.

## Итог урока
- `null` — отсутствие ссылки; обращение к нему падает.
- `?` — пометка «может быть null».
- `??` — значение по умолчанию при null.
- `?.` — безопасное обращение.
- Проверяй данные извне.

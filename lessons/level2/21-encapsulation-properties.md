# Урок 21. Инкапсуляция и свойства

## Цель
Понять, зачем «прятать» данные внутри объекта, и научиться делать это правильно — через свойства.

## Словарик новых слов
- **Инкапсуляция** — «упаковка»: скрытие внутренних данных объекта от постороннего вмешательства. (От слова «капсула» — оболочка.)
- **Поле** — переменная внутри класса (обычно скрытая).
- **Свойство** — «дверца» к полю с проверками: способ дать доступ на чтение/запись, но под контролем.
- **Модификатор доступа** — пометка «кто может видеть». `public` — все, `private` — только сам класс.

## Теория «с нуля»

### Аналогия: приборная панель и двигатель
В машине ты не лезешь руками в двигатель. Ты жмёшь педаль (метод), а за тебя решает механика внутри. Если бы двигатель был открыт — любой мог бы его сломать.
Так и в коде: **внутренние данные лучше прятать**, а доступ давать через специальные «двери» — методы и свойства.

### Что будет без инкапсуляции
```csharp
class BankAccount
{
    public decimal Balance;   // поле открыто — меняем как хотим
}

BankAccount acc = new BankAccount();
acc.Balance = -1000;   // отрицательный баланс! никто не помешал
```

Это плохо: кто угодно может испортить данные.

### Как правильно: скрытое поле + методы
```csharp
class BankAccount
{
    private decimal _balance;   // скрытое поле

    public decimal Balance       // свойство: только чтение
    {
        get { return _balance; }
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("Сумма должна быть положительной");
        _balance += amount;
    }
}
```

Теперь баланс нельзя испортить — он меняется только через `Deposit` с проверкой.

### Свойства с записью
```csharp
class Person
{
    private string _name;

    public string Name
    {
        get { return _name; }
        set
        {
            if (string.IsNullOrWhiteSpace(value))
                throw new ArgumentException("Имя не может быть пустым");
            _name = value;
        }
    }
}
```

- `get` — что вернуть при чтении.
- `set` — что сделать при записи; слово `value` — то значение, которое присваивают.
- Проверка в `set` — защита от мусора.

### Сокращённая запись (auto-property)
Если проверки не нужны:
```csharp
public string Email { get; set; }
```
Компилятор сам создаст скрытое поле. Это самый частый вид свойства.

### Модификаторы
| Ключевое слово | Кто видит |
|---|---|
| `public` | все |
| `private` | только внутри класса |
| `protected` | внутри класса и его наследников |

Правило: **поле — `private`, доступ наружу — через свойства/методы.**

## Сделай сам (задачи с подсказками)

1. Сделай класс `BankAccount` с скрытым полем и методами `Deposit`/`Withdraw` (нельзя уйти в минус).
   *Подсказка: `private decimal _balance;` + проверки в методах.*
2. Класс `Student`: свойство `Age` с проверкой «от 14 до 100».
   *Подсказка: в `set` проверяй `value`, при ошибке бросай исключение.*
3. Класс `Counter`: скрытое поле `_value`, метод `Increment()`, свойство `Value` (только чтение).
   *Подсказка: `public int Value { get { return _value; } }`*
4. Перепиши класс из прошлого урока `Car`: сделай поле `Color` как auto-property.
   *Подсказка: `public string Color { get; set; }`*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Поле `public decimal Balance` | данные открыты, можно испортить | скрой в `private`, дай методы/свойства |
| Свойство без `get` | читать нельзя | добавь `get` |
| `set` без проверки | можно записать мусор | добавляй проверки, где важно |
| `_balance += amount` в методе без условия | можно добавить отрицательное | проверяй `amount` |

## Тест — проверь себя

**Вопрос 1.** Зачем инкапсуляция?
- A) Чтобы программа была красивее.
- B) Чтобы скрыть внутренние данные и защитить их от неправильного изменения.
- C) Чтобы запретить вызывать методы.

✅ **Верно: B.**
Почему: скрытие данных + контроль через проверки защищает состояние объекта.
Почему неверны остальные:
- A — Это не про красоту, а про надёжность.
- C — Методы как раз и остаются доступными.

**Вопрос 2.** Что делает `set` в свойстве?
- A) Возвращает значение.
- B) Обрабатывает запись значения (в `value` лежит то, что присваивают).
- C) Удаляет поле.

✅ **Верно: B.**
Почему: `set` срабатывает при присваивании, `value` — новое значение.
Почему неверны остальные:
- A — Возврат — это `get`.
- C — `set` ничего не удаляет.

**Вопрос 3.** Модификатор `private` означает:
- A) Поле видят все.
- B) Поле видно только внутри этого класса.
- C) Поле видно только внутри сборки.

✅ **Верно: B.**
Почему: `private` — доступ только из самого класса.
Почему неверны остальные:
- A — «Все» — это `public`.
- C — Это описание `internal`, а не `private`.

**Вопрос 4.** Что произойдёт при `acc.Balance = -5;`, если `Balance` — только чтение (только `get`)?
- A) Баланс станет −5.
- B) Произойдёт ошибка: писать нельзя.
- C) Ничего.

✅ **Верно: B.**
Почему: без `set` свойство нельзя присваивать — компилятор даст ошибку.
Почему неверны остальные:
- A — Запись невозможна без `set`.
- C — Ошибка всё-таки будет (на этапе компиляции).

## Итог урока
- **Инкапсуляция** — прячем внутренности, даём контрольный доступ.
- Поля — `private`; наружу — свойства/методы.
- Свойство: `get` (чтение) + `set` (запись) с проверкой через `value`.
- Auto-property `{ get; set; }` — когда проверки не нужны.

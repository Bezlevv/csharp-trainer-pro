# Урок 18. Структура проекта и пространства имён

## Цель
Понять, как устроен проект на диске, что такое namespace и как организовать код в файлы.

## Словарик новых слов
- **Проект** — папка с кодом и файл `.csproj` (настройки).
- **Namespace (пространство имён)** — «папка» для имён классов, чтобы они не конфликтовали.
- **`using`** — «подключить» пространство имён, чтобы не писать его целиком.
- **Solution (.sln)** — объединение нескольких проектов.

## Теория «с нуля»

### Аналогия: квартира и адрес
Представь, что классы — это жильцы. У них есть имена, но «Иван» может быть в разных домах. Адрес (namespace) уточняет, где именно живёт «Иван». Без адресов была бы неразбериха.

### Как выглядит проект на диске
```
MyApp/
├── MyApp.csproj     # настройки: целевая версия .NET и т.п.
├── Program.cs        # входная точка
├── Utils.cs          # ещё один файл с кодом
└── bin/ obj/         # результат сборки (генерируется, в git не нужен)
```

### Зачем namespace
Сгруппировать логически связанные классы и избежать пересечения имён:
```csharp
namespace MyApp.Helpers
{
    public static class MathUtils
    {
        public static int Double(int x) => x * 2;
    }
}
```

### using — подключение
Чтобы использовать класс, либо пишем полное имя, либо подключаем через `using`:
```csharp
using MyApp.Helpers;

int result = MathUtils.Double(5);
```

### Файлы и namespace
Хорошая практика: каждый публичный класс — в отдельном файле, папки повторяют namespace:
```
Utils/
  MathUtils.cs   → namespace MyApp.Helpers
```

### ImplicitUsings
В современных проектах часть стандартных `using` (например, `System`) подключается автоматически (флаг `<ImplicitUsings>enable</ImplicitUsings>` в csproj).

## Примеры

```csharp
// Utils/MathUtils.cs
namespace MyApp.Helpers;

public static class MathUtils
{
    public static int Add(int a, int b) => a + b;
}
```

```csharp
// Program.cs
using MyApp.Helpers;
Console.WriteLine(MathUtils.Add(2, 3));   // 5
```

## Сделай сам (задачи с подсказками)

1. Создай класс в namespace `MyApp.Helpers` с методом `Triple(int)`.
   *Подсказка: `namespace MyApp.Helpers { public static class ... }`*
2. Подключи этот namespace через `using` и вызови метод.
   *Подсказка: `using MyApp.Helpers;` в начале файла.*
3. Разложи два класса по разным файлам и namespace.
   *Подсказка: один класс — один файл.*
4. Объясни, зачем нужен namespace, на примере двух классов с одним именем.
   *Подсказка: разные namespace → нет конфликта.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Забыл `using` | имя не найдено | добавь `using` или пиши полное имя |
| Всё в одном файле | трудно ориентироваться | один публичный класс — один файл |
| Папки не соответствуют namespace | путаница | держи папки и namespace согласованными |
| Забыл `;` после namespace | ошибка компиляции | `namespace ...;` |

## Тест — проверь себя

**Вопрос 1.** Что такое namespace?
- A) Тип данных.
- B) «Пространство имён» — группировка имён классов.
- C) Папка на диске.

✅ **Верно: B.**
Почему: namespace логически группирует имена.
Почему неверны остальные:
- A — Это не тип.
- C — Необязательно совпадает с папкой, хотя принято.

**Вопрос 2.** Зачем `using MyApp.Helpers;`?
- A) Чтобы создать проект.
- B) Чтобы не писать полное имя класса каждый раз.
- C) Чтобы удалить namespace.

✅ **Верно: B.**
Почему: using подключает пространство имён.
Почему неверны остальные:
- A — Это не создание проекта.
- C — Это не удаление.

**Вопрос 3.** Что хранит файл `.csproj`?
- A) Исходный код.
- B) Настройки проекта (целевая версия .NET и т.п.).
- C) Готовую программу.

✅ **Верно: B.**
Почему: csproj — это «паспорт» проекта.
Почему неверны остальные:
- A — Код — в .cs файлах.
- C — Готовая программа — в bin/.

**Вопрос 4.** Что обычно игнорируется в git?
- A) `Program.cs`
- B) `bin/` и `obj/`
- C) `*.csproj`

✅ **Верно: B.**
Почему: bin/obj — результат сборки, они генерируются.
Почему неверны остальные:
- A — Program.cs — исходник, хранится.
- C — csproj — исходник, хранится.

## Итог урока
- Проект = папка + `csproj` + исходники.
- `namespace` — группировка имён; `using` — подключение.
- Один публичный класс — один файл; папки ~ namespace.
- `bin/ obj/` — в `.gitignore`.

# Урок 14. Циклы while и do-while

## Цель
Научиться повторять действия, пока условие истинно (даже если заранее неизвестно, сколько раз).

## Теория «как для ребёнка»

### Пока музыка играет — танцуй
`while` — «пока условие верно, делай». Сколько раз — заранее неизвестно.

```csharp
int x = 0;
while (x < 5)
{
    Console.WriteLine(x);
    x++;
}
```

Работает так:
1. Проверяем условие.
2. Если истинно — выполняем тело.
3. Возвращаемся к проверке.

### Особый случай: while (true)
Бесконечный цикл — «крутись всегда». Хорош, когда выход приходит изнутри через `break`:

```csharp
while (true)
{
    Console.Write("Команда (exit — выход): ");
    string cmd = Console.ReadLine() ?? "";

    if (cmd == "exit") break;   // выход из цикла
    Console.WriteLine($"Выполняю: {cmd}");
}
```

### do-while — «сначала сделай, потом проверь»
Разница: тело выполняется как минимум один раз, проверка — после.

```csharp
string answer;
do
{
    Console.Write("Введи 'да': ");
    answer = Console.ReadLine() ?? "";
}
while (answer != "да");
```

### break и continue
- `break` — полностью выйти из цикла.
- `continue` — перейти сразу к следующей итерации (пропустить остаток тела).

## Примеры

**Ввод числа, пока не введено корректное:**
```csharp
int age;
do
{
    Console.Write("Введи возраст: ");
}
while (!int.TryParse(Console.ReadLine(), out age));

Console.WriteLine($"Возраст: {age}");
```

## Сделай сам (задачи с подсказками)

1. Выведи числа от 1 до 10 через `while`.
   *Подсказка: счётчик `int i = 1;` и условие `while (i <= 10)`.*
2. Запрашивай число, пока пользователь не введёт 0; в конце выведи сумму введённых.
   *Подсказка: `while (true)` + `break` при 0.*
3. «Угадай число»: компьютер загадал, ты угадываешь, подсказки «больше/меньше».
   *Подсказка: `while (guess != secret)` внутри считывай и подсказывай.*
4. Выведи чётные числа до 20 через `while` с `continue`.
   *Подсказка: если число нечётное — `continue`.*
5. Перепиши задачу 1 через `do-while` и сравни поведение.
   *Подсказка: в `do-while` тело гарантированно выполнится хотя бы один раз.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| `while (condition)` без изменения переменных | бесконечный цикл | обязательно меняй что-то в теле |
| `while (true)` без `break` | никогда не закончится | планируй выход изнутри |
| `while` с `;` сразу после скобок | пустое тело | не ставь `;` |
| Путаешь `while` и `do-while` | разные моменты проверки | `do-while` — проверка после, всегда хотя бы один раз |

## Тест — проверь себя

**Вопрос 1.** Сколько раз выполнится тело?
```csharp
int i = 0;
while (i < 3) { Console.WriteLine(i); i++; }
```
- A) 2
- B) 3
- C) 4

✅ **Верно: B.**
Почему: i = 0,1,2 — три итерации (при i=3 условие ложно).
Почему неверны остальные:
- A — 2 было бы при `i < 2`.
- C — 4 было бы при `i <= 3` вместо `i < 3`.

**Вопрос 2.** Чем `do-while` отличается от `while`?
- A) Ничем.
- B) `do-while` проверяет условие после тела, поэтому выполняется хотя бы один раз.
- C) `do-while` нельзя использовать с `break`.

✅ **Верно: B.**
Почему: в `do-while` сначала тело, потом проверка → минимум один проход.
Почему неверны остальные:
- A — Разница есть.
- C — `break` работает в обоих.

**Вопрос 3.** Что произойдёт?
```csharp
while (true) { Console.WriteLine("x"); }
```
- A) Выведется один раз.
- B) Будет печатать "x" бесконечно.
- C) Ошибка компиляции.

✅ **Верно: B.**
Почему: условие всегда истинно, выхода нет.
Почему неверны остальные:
- A — Не остановится на одном.
- C — Такой код компилируется, но зацикливается.

**Вопрос 4.** Что делает `break;` внутри цикла?
- A) Пропускает одну итерацию.
- B) Полностью завершает цикл.
- C) Начинает цикл заново.

✅ **Верно: B.**
Почему: `break` прерывает цикл целиком.
Почему неверны остальные:
- A — Пропуск одной итерации — это `continue`.
- C — Перезапуск цикла — это просто повторное вхождение, а не `break`.

## Итог урока
- `while` — проверка перед выполнением.
- `do-while` — выполнение хотя бы один раз.
- `while (true)` + `break` — вечный цикл с управляемым выходом.
- `break` — выход, `continue` — пропуск итерации.

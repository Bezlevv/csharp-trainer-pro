# Урок 17. Отладка и чтение ошибок

## Цель
Научиться понимать сообщения об ошибках и находить, что сломалось.

## Словарик новых слов
- **Компилятор** — переводчик с C# на исполняемый код. Если он не понял — показывает ошибку.
- **Ошибка компиляции** — «статическая» ошибка: код неверен, программа не соберётся.
- **Ошибка во время выполнения (runtime)** — код собрался, но упал в процессе.
- **Трассировка стека (stack trace)** — список вызовов, который показывает, где случилась ошибка.
- **Отладка** — процесс поиска и исправления ошибок.

## Теория «с нуля»

### Аналогия: переводчик и шеф-повар
Компилятор — капризный переводчик: если ты сделал опечатку — он не «догадывается», а честно указывает строку. А ошибка во время выполнения — как рецепт, который собрался, но при готовке что-то пошло не так. Главное — **читать сообщения**, а не пугаться.

### Виды ошибок

**1. Ошибка компиляции — программа не собирается**
```csharp
Console.WriteLine("Привет")   // забыли ;
```
Сообщение компилятора: `; expected` (ожидалась точка с запятой) и номер строки. Ошибку видно сразу.

**2. Ошибка во время выполнения — программа упала**
```csharp
int x = int.Parse("пять");   // FormatException
```
Программа *собралась*, но при запуске бросила исключение.

### Как читать ошибку
Сообщение обычно содержит:
- **тип ошибки** (например, `FormatException`);
- **объяснение** («Input string was not in a correct format»);
- **строку и файл**, где случилось.

### Трассировка стека
Когда падает, C# показывает цепочку вызовов — от места падения вверх. Читай **самую верхнюю строку** — это место, где реально случилась ошибка, а не вся цепочка.

### Приёмы отладки без отладчика
- Выводи промежуточные значения: `Console.WriteLine($"debug: {variable}")`.
- Проверяй входные данные перед использованием.
- Читай строчку, на которую указывает ошибка, буквально.

## Примеры

**Частая ошибка: выход за границы массива**
```csharp
int[] a = { 1, 2, 3 };
Console.WriteLine(a[5]);   // IndexOutOfRangeException
```
Сообщение укажет на строку с `a[5]`. Индекс 5 не существует (есть 0..2).

## Сделай сам (задачи с подсказками)

1. Сделай 3 намеренные ошибки (забытый `;`, опечатка в `Console`, неверный тип) и запиши, что говорит компилятор.
   *Подсказка: компилятор почти всегда указывает строку и номер.*
2. Вызови `int.Parse("abc")` без try/catch и прочитай тип исключения.
   *Подсказка: это FormatException.*
3. Обратись к `array[10]` в массиве из 3 элементов; запиши сообщение.
   *Подсказка: это IndexOutOfRangeException.*
4. Добавь `Console.WriteLine` для отладки внутри метода и найди, где значение становится неверным.
   *Подсказка: печатай значение до и после операции.*

## Разбор типичных ошибок

| Ошибка | Что не так | Как правильно |
|---|---|---|
| Игнорировать сообщение об ошибке | теряешь главную подсказку | читай тип, объяснение и строку |
| Паниковать при стек-трейсе | большая простыня пугает | смотри только верхнюю строку |
| «Мне кажется, ошибка где-то тут» | бессистемный поиск | выводи отладочные значения и сужай круг |
| Менять всё подряд наугад | ломаешь рабочее | правь одну строку и проверяй заново |

## Тест — проверь себя

**Вопрос 1.** Где компилятор указывает место ошибки?
- A) Нигде, надо искать самому.
- B) В сообщении: файл и номер строки.
- C) Всегда в конце программы.

✅ **Верно: B.**
Почему: компилятор сообщает файл и строку.
Почему неверны остальные:
- A — Указывает.
- C — Не «всегда в конце».

**Вопрос 2.** Чем ошибка компиляции отличается от ошибки во время выполнения?
- A) Ничем.
- B) Компиляция: код не собрался; runtime: собрался, но упал при запуске.
- C) Runtime бывает только на Linux.

✅ **Верно: B.**
Почему: это два разных этапа.
Почему неверны остальные:
- A — Разница есть.
- C — Не связано с ОС.

**Вопрос 3.** Что такое трассировка стека?
- A) Список команд компьютера.
- B) Цепочка вызовов, показывающая, где случилась ошибка.
- C) Резервная копия кода.

✅ **Верно: B.**
Почему: стек-трейс показывает путь вызовов.
Почему неверны остальные:
- A — Это не «команды компьютера».
- C — Это не копия.

**Вопрос 4.** `int.Parse("abc")` — это:
- A) Ошибка компиляции.
- B) Ошибка во время выполнения (FormatException).
- C) Валидный код без ошибок.

✅ **Верно: B.**
Почему: код компилируется, но при запуске падает.
Почему неверны остальные:
- A — Компилируется нормально.
- C — При запуске упадёт.

## Итог урока
- Ошибки бывают на этапе компиляции и во время выполнения.
- Читай тип ошибки, объяснение и строку.
- В стек-трейсе смотри верхнюю строку.
- Используй `Console.WriteLine` для отладки.

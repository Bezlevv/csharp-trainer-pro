# Модуль 04: ООП — классы и инкапсуляция

> **Цель:** проектировать собственные типы данных через классы, скрывать внутренности (инкапсуляция) и грамотно управлять состоянием.

## Зачем это нужно

До сих пор мы работали с примитивами: `int`, `string`. Но в реальном мире данные имеют структуру: у человека есть имя, возраст и почта; у счёта — номер и баланс; у заказа — список позиций и сумма. Если хранить всё в отдельных переменных, код быстро превращается в кашу. Классы позволяют сгруппировать данные и поведение в один тип — это ООП (объектно-ориентированное программирование).

## Теория

### 1. Четыре столпа ООП

| Столп | Идея | Где разберём |
|---|---|---|
| **Инкапсуляция** | скрыть внутреннее состояние, дать доступ через методы | этот модуль |
| **Наследование** | общие свойства вынести в базовый класс | модуль 05 |
| **Полиморфизм** | один интерфейс — разные реализации | модуль 05 |
| **Абстракция** | скрыть сложность за понятным интерфейсом | модуль 05/14 |

### 2. Класс и объект

**Класс** — чертёж (тип). **Объект** — конкретный экземпляр по этому чертёжу.

```csharp
class Person
{
    public string Name;   // поле
    public int Age;
}
```

Создание объектов:

```csharp
Person p1 = new Person { Name = "Иван", Age = 30 };
Person p2 = new Person { Name = "Мария", Age = 28 };
```

### 3. Поля и свойства

**Поля** — обычные переменные в классе. Но поля напрямую раскрывать наружу не принято — для этого есть свойства.

**Свойства** — пара методов-аксессоров:

```csharp
class BankAccount
{
    private decimal _balance; // поле: скрыто

    public decimal Balance       // свойство: публичный доступ
    {
        get => _balance;
        private set => _balance = value;
    }

    public decimal Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
        return _balance;
    }
}
```

**Auto-property** — свойство без явно объявленного поля:

```csharp
public string Name { get; set; }   // читать и записывать
public string Email { get; init; } // можно задать только при создании
```

### 4. Модификаторы доступа

| Модификатор | Где виден |
|---|---|
| `public` | везде |
| `private` | только внутри класса |
| `protected` | внутри класса и наследников (модуль 05) |
| `internal` | внутри сборки |

**Золотое правило:** поле/состояние должно быть `private`; наружу отдавай свойства и методы. Это и есть инкапсуляция — никто не может испортить баланс, минуя `Deposit`.

### 5. Конструкторы

Конструктор — метод, вызываемый при создании объекта. Имя совпадает с именем класса, возвращаемого типа нет.

```csharp
class Person
{
    public string Name { get; }

    public Person(string name)
    {
        if (string.IsNullOrWhiteSpace(name))
            throw new ArgumentNullException(nameof(name));

        Name = name;
    }
}
```

**Перегрузка конструкторов и `this()`:**

```csharp
class Point
{
    public int X { get; }
    public int Y { get; }

    public Point(int x, int y) { X = x; Y = y; }
    public Point() : this(0, 0) { } // делегируем «центральному» конструктору
}
```

**Object initializer** — задание свойств при создании:

```csharp
var p = new Person("Иван") { Age = 30 };
```

### 6. `readonly`, `const`, `static readonly`

- `const` — константа времени компиляции, часть типа.
- `static readonly` — значение создаётся один раз при первом обращении к типу.

```csharp
class Config
{
    public const int MaxRetries = 3;
    public static readonly DateTime Epoch = new DateTime(1970, 1, 1);
}
```

### 7. Статические члены

Статические члены принадлежат типу, а не объекту. Общие для всех экземпляров.

```csharp
class Counter
{
    public static int Created;       // сколько всего объектов создано
    public Counter() => Created++;
}
```

```csharp
var a = new Counter();
var b = new Counter();
Console.WriteLine(Counter.Created); // 2
```

**Статические классы** — нельзя создавать объекты; только статические члены. Примеры в BCL: `Math`, `File`, `Console`.

```csharp
static class TemperatureConverter
{
    public static double CelsiusToFahrenheit(double c) => c * 9 / 5 + 32;
}
```

### 8. `record` — введение

`record` — ссылочный тип с value-равенством (модуль 06). Компилятор сам генерирует `Equals`, `GetHashCode`, `ToString`.

```csharp
record Person(string Name, int Age);
```

```csharp
var p1 = new Person("Иван", 30);
var p2 = new Person("Иван", 30);
Console.WriteLine(p1 == p2); // True — по значениям, а не по ссылке
```

### 9. Nullable reference types

Модификатор `?` сообщает: «может быть null».

```csharp
string? maybe = null;       // может быть null
string required = "текст";   // не должен быть null
```

Компилятор предупредит, если ты разыменуешь `maybe` без проверки. Операторы `??` и `?.` уже знакомы из модуля 01.

## Типичные ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| публичные поля `public int Balance` | состояние меняют напрямую, валидация обходится | свойства с `private set` или методы |
| «проваливание» инкапсуляции | наружу отдаётся внутренняя коллекция, которую меняют | `IReadOnlyList<T>` (модуль 07) |
| вся логика в `Program` | God-класс, нетестируемо | разбить на классы по смыслу |
| общий изменяемый `static`-стат | гонки, неожиданные изменения из любого места | использовать осторожно, только по делу |
| дублирование кода в конструкторах | лишние повторы | делегирование через `this()` |

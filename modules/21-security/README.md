# Модуль 21: Безопасность веб-приложений

> **Цель:** защищать API: аутентификация, авторизация, секреты и типичные уязвимости.

## Зачем это нужно

Выложить API в интернет без защиты — значит дать злоумышленникам доступ к данным. Безопасность — навык senior: понимать, как аутентифицировать пользователей, как разграничивать права и как не подставиться под типичные атаки (OWASP Top 10).

## Теория

### 1. Аутентификация vs авторизация

- **Аутентификация** — «кто ты?» (проверка личности).
- **Авторизация** — «что тебе можно?» (права).

### 2. JWT (JSON Web Token)

Популярный способ аутентификации API:

- При логине сервер выдаёт подписанный токен.
- Клиент шлёт его в заголовке `Authorization: Bearer <token>`.
- Сервер проверяет подпись, не обращаясь к БД на каждый запрос.

```csharp
// регистрация схемы JWT
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidIssuer = issuer,
            ValidAudience = audience,
            IssuerSigningKey = new SymmetricSecurityKey(keyBytes)
        };
    });
```

**Секрет ключа** — в конфигурации/env-переменных, никогда в коде.

### 3. Авторизация на основе ролей

```csharp
app.MapGet("/admin", () => "Админ")
   .RequireAuthorization("Admin");
```

Политики и роли — через `AddAuthorization`.

### 4. Секреты

- Хранить в переменных окружения, user-secrets или в безопасном хранилище (Vault).
- **Никогда**: ключи в репозитории, в `appsettings.json` в репо.

### 5. OWASP Top 10 (главное)

| Уязвимость | Защита |
|---|---|
| SQL-инъекции | параметризованные запросы / EF Core (не сырые строки) |
| XSS | не выводить пользовательские данные как HTML без экранирования |
| Подделка запроса (CSRF) | анти-в-RF-токены, проверка Origin |
| Слабые пароли | хэширование (bcrypt/Argon2), политика сложности |
| Утечка данных | ограничить доступ, шифрование, логировать аккуратно |
| Небезопасная десериализация | не принимать произвольные типы |

### 6. Проверка входных данных

Валидация на границе API (модели запросов), а не только на клиенте.

## Типичные ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Секреты в коде/репо | утечка | env-переменные, Vault |
| Отсутствие `RequireAuthorization` | открытые эндпоинты | защищать по необходимости |
| Хранение паролей в открытом виде | кража паролей | хэширование |
| Доверие входным данным | инъекции | валидация и параметризация |

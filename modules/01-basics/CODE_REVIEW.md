# Разбор кода — Модуль 01

> Формат: рабочий, но плохой код → находим проблемы → рефакторим.

## Пример 1: Магические числа

### Исходный код

```csharp
double price = 499;
double tax = price * 0.2;
Console.WriteLine($"Цена с налогом: {price + tax}");
```

### Что не так

- `0.2` — налоговая ставка, зашитая «магическим числом». Через месяц никто не вспомнит, что значит `0.2`. При изменении налога придётся искать все вхождения.

### Как лучше

```csharp
const double TaxRate = 0.2;
double price = 499;
double tax = price * TaxRate;
Console.WriteLine($"Цена с налогом: {price + tax}");
```

### Вывод

Именованные константы объясняют смысл чисел. Менять `TaxRate` — одно место, а не десяток строк.

## Пример 2: `double` для денег

### Исходный код

```csharp
double total = 0;
for (int i = 0; i < 1000; i++)
{
    total += 0.1;
}
Console.WriteLine(total); // 99.9999999999986 — НЕ 100!
```

### Что не так

- `double` хранит числа неточно. При накоплении мелких приращений ошибка растёт.

### Как лучше

```csharp
decimal total = 0m;
for (int i = 0; i < 1000; i++)
{
    total += 0.1m;
}
Console.WriteLine(total); // 100.0
```

### Вывод

Для денег, процентов и всего, где важна точность, — только `decimal`. `double` — для научных расчётов, где точность до 15-17 знака не критична.

## Пример 3: Склейка строк в цикле

### Исходный код

```csharp
string result = "";
for (int i = 0; i < 10000; i++)
{
    result += "x"; // создаётся 10000 промежуточных строк
}
```

### Что не так

- Строки неизменяемы. Каждое `+=` создаёт **новую** строку, копируя старую. Итог — 10 000 аллокаций и квадратичная сложность.

### Как лучше

```csharp
var sb = new System.Text.StringBuilder();
for (int i = 0; i < 10000; i++)
{
    sb.Append('x');
}
string result = sb.ToString();
```

### Вывод

`StringBuilder` мутирует внутренний буфер без создания новых строк. Для небольшого числа операций (до ~10) интерполяция или `string.Join` — проще; для циклов — `StringBuilder`.

## Пример 4: Переполнение int

### Исходный код

```csharp
int secondsInYear = 60 * 60 * 24 * 365;
Console.WriteLine(secondsInYear); // -1461241 (переполнение!)
```

### Что не так

- `60 * 60 * 24 * 365` переполняет `int`: результат не влезает в 4 байта, и мы получаем отрицательное число.

### Как лучше

```csharp
long secondsInYear = 60L * 60 * 24 * 365; // суффикс L — long
Console.WriteLine(secondsInYear); // 31536000
```

### Вывод

Всегда думай о диапазоне типа. Суффикс `L` заставляет вычисления идти в `long`.

## Пример 5: `Parse` без обработки ошибок

### Исходный код

```csharp
Console.Write("Введи число: ");
int number = int.Parse(Console.ReadLine()!);
Console.WriteLine($"Квадрат: {number * number}");
```

### Что не так

- Если пользователь введёт `abc`, программа упадёт с `FormatException`. Ввод из консоли — ненадёжный источник данных.

### Как лучше

```csharp
Console.Write("Введи число: ");
if (int.TryParse(Console.ReadLine(), out int number))
{
    Console.WriteLine($"Квадрат: {number * number}");
}
else
{
    Console.WriteLine("Некорректное число");
}
```

### Вывод

`TryParse` — стандарт для разбора пользовательского ввода: не падает, а сигнализирует результатом `bool`.

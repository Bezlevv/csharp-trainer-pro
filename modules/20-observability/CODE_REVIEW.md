# Разбор кода — Модуль 20

> Формат: плохой код наблюдаемости → находим проблемы → рефакторим.

## Пример 1: Конкатенация в логах

### Исходный код

```csharp
_logger.LogInformation($"Заказ {order.Id} создан");
```

### Что не так

- Строка собирается до вызова: параметр не структурирован, фильтрация и агрегация невозможны.

### Как лучше

```csharp
_logger.LogInformation("Заказ {OrderId} создан", order.Id);
```

### Вывод

Параметры `{...}` — основа структурированного логирования.

## Пример 2: Пустой catch

### Исходный код

```csharp
catch (Exception)
{
    // тишина
}
```

### Что не так

- Ошибка теряется. Невозможно расследовать инцидент.

### Как лучше

```csharp
catch (Exception ex)
{
    _logger.LogError(ex, "Не удалось обработать заказ {OrderId}", order.Id);
    throw;
}
```

### Вывод

Логируй ошибки с исключением и перебрасывай.

## Пример 3: Логирование секретов

### Исходный код

```csharp
_logger.LogInformation("Авторизация пользователя {Token}", token);
```

### Что не так

- Секрет попадает в логи. Это утечка.

### Как лучше

Никогда не логировать пароли, токены, ключи. Логировать id пользователя, но не секрет.

### Вывод

Секреты — не для логов.

## Пример 4: Info вместо Warning для ошибок

### Исходный код

```csharp
_logger.LogInformation("Оплата не прошла: {Message}", ex.Message);
```

### Что не так

- Сбой записан как обычное событие — алерты не сработают.

### Как лучше

```csharp
_logger.LogWarning("Оплата отклонена {OrderId}: {Reason}", order.Id, reason);
```

### Вывод

Уровень должен отражать серьёзность.

## Пример 5: «Лог-водопад»

### Исходный код

```csharp
_logger.LogInformation("Шаг 1");
// ...
_logger.LogInformation("Шаг 2");
// ... десятки шагов
```

### Что не так

- Шум. Трудно найти главное.

### Как лучше

Логировать значимые события и ошибки, а не каждый шаг. Для детального разбора — трейсы.

### Вывод

Качество важнее количества логов.

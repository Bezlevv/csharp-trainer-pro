# Модуль 22: Docker и деплой .NET-приложений

> **Цель:** упаковать .NET-приложение в контейнер и понять, как оно деплоится.

## Зачем это нужно
Docker — стандарт доставки приложений. Контейнер «упаковывает» код + окружение, и приложение одинаково работает на любой машине. Для senior-уровня это обязательный навык.

## Теория

### 1. Что такое контейнер
Контейнер — изолированный процесс с **собственным окружением** (файлы, переменные, зависимости). В отличие от виртуальной машины, он использует ядро хоста и потому лёгкий и быстрый.

### 2. Образ (image) и контейнер (container)
- Образ — «шаблон» (как класс). Собирается из `Dockerfile`.
- Контейнер — запущенный экземпляр образа (как объект).

### 3. Dockerfile для .NET
```dockerfile
# этап 1: сборка
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish src/TaskApi/TaskApi.csproj -c Release -o /app

# этап 2: рантайм (меньше)
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=build /app .
EXPOSE 8080
ENTRYPOINT ["dotnet", "TaskApi.dll"]
```

Многоступенчатая сборка: SDK нужен только для компиляции, в образе — только рантайм (меньше и безопаснее).

### 4. Основные команды

```bash
docker build -t my-api .          # собрать образ
docker run -p 8080:8080 my-api    # запустить контейнер
docker ps                         # список работающих контейнеров
docker stop <id>                  # остановить
docker compose up                 # поднять всё из docker-compose.yml
```

### 5. docker-compose.yml
Для нескольких сервисов (API + БД):
```yaml
services:
  api:
    build: .
    ports: ["8080:8080"]
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
```

### 6. Переменные окружения в контейнере
Секреты и конфигурацию передают не в образ, а при запуске:
```bash
docker run -e "JWT_SECRET=..." -e "DB_CONNECTION=..." my-api
```

### 7. Публикация образа
```bash
docker tag my-api myuser/my-api:latest
docker push myuser/my-api:latest   # на Docker Hub
```

## Типичные ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Копировать весь SDK в образ | образ огромный | многоступенчатая сборка |
| Хардкодить секреты в Dockerfile | утечка | `-e` / переменные окружения |
| Не указывать `EXPOSE` | порт не виден | `EXPOSE 8080` |
| Кэш не используется | каждая сборка с нуля | порядок COPY: сначала зависимости |

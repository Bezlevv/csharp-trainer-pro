# Разбор кода — Модуль 02

> Формат: рабочий, но плохой код → находим проблемы → рефакторим.

## Пример 1: Стрелочная кодировка (`else` после `return`)

### Исходный код

```csharp
string CheckAccess(int age)
{
    if (age >= 18)
    {
        return "Доступ разрешён";
    }
    else
    {
        return "Доступ запрещён";
    }
}
```

### Что не так

- `else` после `return` избыточен: если условие истинно, метод уже завершился. Остаётся лишний уровень вложенности.

### Как лучше

```csharp
string CheckAccess(int age)
{
    if (age >= 18)
        return "Доступ разрешён";

    return "Доступ запрещён";
}
```

### Вывод

Ранний выход `return` убирает `<else` и делает логику плоской. Чем меньше вложенности — тем легче читать.

## Пример 2: Дублирование условий в цепочке

### Исходный код

```csharp
if (score >= 90)
{
    grade = "A";
}
else if (score >= 80)
{
    grade = "B";
}
else if (score >= 70)
{
    grade = "C";
}
else if (score >= 60)
{
    grade = "D";
}
else
{
    grade = "F";
}
```

### Что не так

- Проверки дублируют границы (`>= 90`, затем `>= 80`). Порядок критичен, легко ошибиться, всё вручную.

### Как лучше

```csharp
string grade = score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 70 => "C",
    >= 60 => "D",
    _ => "F"
};
```

### Вывод

`switch`-выражение с реляционными паттернами — выразительнее и не даёт дублировать границы.

## Пример 3: Бесконечный цикл без управляемого выхода

### Исходный код

```csharp
while (true)
{
    Console.WriteLine("Меню: 1 — Каталог, 2 — Выход");
    string input = Console.ReadLine() ?? "";

    if (input == "1")
    {
        Console.WriteLine("Каталог...");
        // программа зависнет после выбора 1
    }
}
```

### Что не так

- Ветка «Выход» не обрабатывается вообще — пользователь не может выйти, цикл вечный.

### Как лучше

```csharp
while (true)
{
    Console.WriteLine("Меню: 1 — Каталог, 2 — Выход");
    string input = Console.ReadLine() ?? "";

    switch (input)
    {
        case "1":
            Console.WriteLine("Каталог...");
            break;
        case "2":
            return; // выход из программы
        default:
            Console.WriteLine("Неверная команда");
            break;
    }
}
```

### Вывод

Вечный цикл обязан иметь гарантированный выход. `return` из `Main` — чистый способ завершить программу.

## Пример 4: Глубокая вложенность

### Исходный код

```csharp
if (isUser)
{
    if (isAdmin)
    {
        if (isActive)
        {
            Console.WriteLine("Панель администратора");
        }
    }
}
```

### Что не так

- Три уровня вложенности. Добавишь ещё условие — код утонет в скобках. «А»-логика прячется в глубине.

### Как лучше

```csharp
if (!isUser || !isAdmin || !isActive)
{
    return;
}

Console.WriteLine("Панель администратора");
```

### Вывод

Guard clauses инвертируют условия и выходят рано. Условие «все признаки есть» становится единственным, что остаётся после проверок.

## Пример 5: Сложное условие с `&&` / `||`

### Исходный код

```csharp
if ((age >= 18 && age <= 60 && !isStudent) || (age >= 60 && age <= 80 && isPensioner))
```

### Что не так

- В одно выражение навалено всё. Читаемость нулевая, трудно отлаживать.

### Как лучше

```csharp
bool IsEligible()
{
    if (age is >= 18 and <= 60 && !isStudent)
        return true;

    if (age is >= 60 and <= 80 && isPensioner)
        return true;

    return false;
}
```

### Вывод

Разбивай сложные условия на проверяемые куски. Реляционные паттерны `is >= 18 and <= 60` читаются как «в диапазоне».

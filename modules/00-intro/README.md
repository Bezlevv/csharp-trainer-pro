# Модуль 00: Введение в C# и .NET

> **Цель:** понять, что такое C# и .NET, установить SDK, создать первую программу и разобраться, что происходит под капотом.

## Зачем это нужно

Когда ты начинаешь с C#, важно сразу понять две вещи: **язык** и **платформу**. C# — это язык программирования: правила, по которым ты пишешь код. .NET — это платформа: она превращает твой код в работающую программу и даёт огромную библиотеку готовых инструментов (работа с файлами, сетью, JSON, коллекциями и т.д.).

Многие новички путаются: «Почему мы устанавливаем .NET SDK, если учим C#?» Ответ простой — без .NET код на C# не запустится. Но и без C# платформа бесполезна. Это как автомобиль: C# — это правила дорожного движения, а .NET — сам автомобиль. Оба нужны вместе.

Индустрия любит C# за три вещи:

- **Надёжность** — строгая типизация ловит огромную долю ошибок ещё на этапе компиляции, до запуска программы.
- **Мощность** — язык развивается очень активно: каждый год выходят новые возможности, которые делают код короче и безопаснее.
- **Скорость разработки** — .NET «из коробки» даёт решение большинства рутинных задач.

## Теория

### 1. Что такое C# и .NET

C# (произносится «си-шарп») — язык программирования, созданный компанией Microsoft в 2000-х. На нём пишут:

- десктопные приложения (Windows);
- веб-сервисы и API (ASP.NET Core);
- мобильные приложения (через .NET MAUI / Xamarin);
- игры (Unity);
- облачные сервисы;
- фоновые службы и многое другое.

.NET — это **платформа**. Её ключевые части:

| Компонент | Что делает |
|---|---|
| **CLR** (Common Language Runtime) | «движок»: управляет памятью, потоками, запускает код |
| **BCL** (Base Class Library) | огромная коллекция готовых классов: `Console`, `File`, `String`, `List<T>`, `HttpClient` и тысячи других |
| **SDK** | набор инструментов для разработки: компилятор, утилиты командной строки |
| **Runtime** | среда для запуска готовых программ у пользователя |

### 2. Как код превращается в программу

C# — компилируемый язык, но не совсем так, как C++ (где сразу получается машинный код). Процесс двухступенчатый:

1. **Компилятор** (который входит в SDK) превращает твой исходный код `.cs` в промежуточный код **IL** (Intermediate Language). Он «почти машинный», но ещё не привязан к конкретному процессору.
2. **JIT-компилятор** (Just-In-Time), который живёт внутри CLR, при запуске программы на лету превращает IL в машинный код конкретного процессора.

Это даёт важное преимущество: одна и та же программа на IL может работать на Windows, Linux и macOS — платформа адаптируется под каждую ОС.

> **Аналогия.** Представь, что ты написал рецепт (исходный код). Повар (компилятор) переписывает его на универсальный язык кухонных операций (IL). А на каждой конкретной кухне (ОС) другой повар (JIT) переводит это в конкретные движения рук и приборов (машинный код).

### 3. Установка SDK

Качаем **.NET SDK** (не Runtime!) с официального сайта [dotnet.microsoft.com/download](https://dotnet.microsoft.com/download).

- **SDK** нужен разработчику — он содержит компилятор и инструменты.
- **Runtime** нужен только для запуска готовых программ.

Проверяем установку:

```bash
dotnet --version
```

Ты увидишь номер версии, например `8.0.100`. Это значит, что SDK установлен и работает.

### 4. dotnet CLI — главный инструмент

CLI (Command Line Interface) — это команды в терминале. Вот самые важные:

| Команда | Что делает |
|---|---|
| `dotnet new console -n MyApp` | создаёт новый консольный проект `MyApp` |
| `dotnet build` | компилирует проект в папке |
| `dotnet run` | собирает и запускает программу |
| `dotnet restore` | скачивает зависимые пакеты NuGet |
| `dotnet test` | запускает тесты |

Попробуем:

```bash
dotnet new console -n HelloWorld
cd HelloWorld
dotnet run
```

Ты увидишь `Hello, World!` — твою первую работающую программу.

### 5. Анатомия проекта

Заглянем в папку проекта:

```
HelloWorld/
├── HelloWorld.csproj   # файл проекта: настройки и зависимости
├── Program.cs           # исходный код программы
├── bin/                 # результат сборки (генерируется)
└── obj/                 # промежуточные файлы сборки (генерируются)
```

- `Program.cs` — здесь живёт код. `bin/` и `obj/` генерируются автоматически, их **не нужно** хранить в системе контроля версий (для этого есть `.gitignore`).
- Файл `.csproj` — XML-файл с настройками проекта. В современных версиях он очень короткий:

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
```

### 6. Top-level statements

Посмотрим на `Program.cs`:

```csharp
Console.WriteLine("Hello, World!");
```

Это всего одна строка! Раньше нужно было писать гораздо больше:

```csharp
using System;

namespace HelloWorld
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}
```

Начиная с C# 9, компилятор позволяет писать код «вне класса» — это называется **top-level statements**. Программа упростилась в разы. Понимать старый синтаксис всё равно полезно (он встречается в чужих проектах), но писать проще.

### 7. NuGet

**NuGet** — это менеджер пакетов .NET, как pip в Python или npm в Node.js. Пакет — это готовая библиотека, которую можно подключить к проекту одной командой.

Подключить пакет:

```bash
dotnet add package Humanizer
```

Эта команда добавит пакет в `.csproj`, и его можно будет использовать. Сейчас в NuGet сотни тысяч пакетов — от маленьких утилит до целых фреймворков.

### 8. Первые программы

**Приветствие:**

```csharp
Console.WriteLine("Привет, мир!");
Console.Write("Как тебя зовут? ");
string name = Console.ReadLine() ?? "";
Console.WriteLine($"Приятно познакомиться, {name}!");
```

Обрати внимание: `Console.WriteLine("Привет")` — выводит строку, а `Console.ReadLine()` — считывает ввод пользователя. Символ `$` перед строкой включает **интерполяцию** — подстановку значений переменных в строку. Полное название этого механизма — `$""` с фигурными скобками. Об этом подробнее в следующем модуле.

**Числа:**

```csharp
int a = 5;
int b = 7;
Console.WriteLine($"Сумма: {a + b}");
```

**Чтение чисел из консоли:**

```csharp
int age = int.Parse(Console.ReadLine()!);
```

`int.Parse` преобразует строку (то, что ввёл пользователь) в число. Восклицательный знак `!` говорит компилятору: «Я знаю, что тут не будет null». Про nullable-типы поговорим в модуле 04.

## Типичные ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Копировать код без понимания | Ты не запоминаешь, что происходит, и не можешь исправить ошибку | Набирай каждую программу руками и разбирай каждую строку |
| Не игнорировать `bin/` и `obj/` | Засоряешь репозиторий мусором, который генерируется автоматически | Добавь `.gitignore` с `bin/` и `obj/` |
| «У меня работает в Visual Studio» | Другие не смогут запустить без тех же настроек | Проверяй запуск через `dotnet run` в чистом терминале |
| Жёстко зашивать значения в код | Чинить такой код больно | Используй переменные и аргументы |

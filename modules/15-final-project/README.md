# Модуль 15: Итоговый проект — Task Tracker

> **Цель:** собрать все знания курса в законченное приложение с архитектурой, слоями и тестами.

## О проекте

**Task Tracker** — консольный трекер задач. Поддерживает:

- добавление задач с приоритетом и дедлайном;
- просмотр, фильтрация по статусу;
- завершение, изменение приоритета, удаление;
- сохранение в JSON-файл при каждом изменении.

## Архитектура

```
┌──────────────────────────────────────────────────────┐
│                    Program.cs                        │  входная точка: DI-сборка
└──────────────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────────────┐
│                    Cli/ConsoleUI                     │  меню, ввод, вывод
└──────────────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────────────┐
│                Services/TaskService                  │  бизнес-логика, валидация
└──────────────────────────────────────────────────────┘
                      │
┌──────────────────────────────────────────────────────┐
│         Storage/ITaskRepository   (интерфейс)        │  контракт
│         Storage/JsonTaskRepository (реализация)      │  JSON-хранилище
└──────────────────────────────────────────────────────┘
```

Слои зависят вниз: UI → сервис → хранилище. Бизнес-логика **не знает** про JSON — она зависит от интерфейса `ITaskRepository`.

## Запуск и тесты

Из папки `task-tracker`:

```bash
# Запуск приложения
dotnet run --project src/TaskTracker

# Тесты
dotnet test
```

Данные сохраняются в `data/tasks.json` относительно текущей папки.

## Ключевые решения

| Решение | Почему |
|---|---|
| Слои (Models / Services / Storage / Cli) | единая ответственность (SRP), проект легко расширять |
| `ITaskRepository` + `JsonTaskRepository` | инверсия зависимостей (DIP): сервис можно тестировать без файлов |
| Своё исключение `InvalidTaskOperationException` | понятная диагностика ошибок домена |
| `record TaskItem` | неизменяемые данные, value-равенство |
| `required` + `init` | безопасное создание модели без «наполовину построенных» объектов |
| Асинхронность до конца (async/await) | не блокируем поток при работе с файлом |
| `CancellationToken` пробрасывается | отменяемость операций |
| Диагностика битого JSON (без падения) | приложение остаётся живым в худшем случае |

# Модуль 05: Наследование и полиморфизм

> **Цель:** строить иерархии типов, переопределять поведение и правильно выбирать между наследованием и интерфейсами.

## Зачем это нужно

Когда в программе появляются «родственные» типы — круг и квадрат, кошка и собака, сберегательный и кредитный счёт, — хочется переиспользовать общий код и обращаться с ними единообразно. Это и дают **наследование** и **полиморфизм**. Без них приходится писать кучу `if`-ов по типу, что хрупко и разрастётся.

## Теория

### 1. Наследование

Класс-наследник получает члены базового класса.

```csharp
class Animal
{
    public string Name { get; set; }

    public void Eat() => Console.WriteLine($"{Name} ест");
}

class Dog : Animal
{
    public void Bark() => Console.WriteLine("Гав!");
}
```

```csharp
var dog = new Dog { Name = "Рекс" };
dog.Eat();   // из базового класса
dog.Bark();  // своё
```

**Ограничение:** в C# только **одиночное** наследование — один базовый класс.

#### Конструкторы и `base`

```csharp
class Animal
{
    public string Name { get; }
    public Animal(string name) => Name = name;
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }
}
```

Наследник обязан вызвать базовый конструктор через `base(...)`.

### 2. Виртуальные методы: `virtual` / `override`

```csharp
class Animal
{
    public virtual string Speak() => ".....";
}

class Dog : Animal
{
    public override string Speak() => "Гав!";
}
```

- `virtual` — метод можно переопределить.
- `override` — наследник меняет поведение.

### 3. Полиморфизм

Ссылка базового типа может указывать на объект наследника:

```csharp
Animal a = new Dog();
Console.WriteLine(a.Speak()); // "Гав!" — вызывается переопределённый метод
```

Что важно: **какой метод вызовется, решается в рантайме** по фактическому типу объекта. Это называется виртуальная диспетчеризация.

```csharp
Animal[] animals = { new Dog(), new Cat(), new Cow() };
foreach (Animal animal in animals)
{
    Console.WriteLine(animal.Speak());
}
```

### 4. Абстрактные классы и методы

`abstract` — класс, который нельзя инстанцировать. Может содержать абстрактные методы — без тела, их обязаны реализовать наследники.

```csharp
abstract class Shape
{
    public abstract double Area();
}

class Circle : Shape
{
    public double Radius { get; }
    public Circle(double radius) => Radius = radius;
    public override double Area() => Math.PI * Radius * Radius;
}
```

```csharp
// var s = new Shape(); // Ошибка: абстрактный класс нельзя создать
Shape s = new Circle(2);
Console.WriteLine(s.Area());
```

### 5. `sealed`

`sealed` — запрещает наследование (или переопределение метода):

```csharp
sealed class Point2D { }
// class Derived : Point2D { } // Ошибка
```

### 6. Переопределение `ToString` и `Equals`

`object` — корень всех типов. Его виртуальные методы можно переопределять:

```csharp
class Person
{
    public string Name { get; }
    public Person(string name) => Name = name;

    public override string ToString() => $"Человек: {Name}";
}
```

```csharp
Console.WriteLine(new Person("Иван")); // "Человек: Иван"
```

Про `Equals`/`GetHashCode` подробнее поговорим в модуле 06 (там же — `record`).

### 7. Интерфейсы

Интерфейс — «контракт»: набор членов, которые обязана реализовать реализация. Члены интерфейса не имеют тела.

```csharp
interface IShape
{
    double Area();
}
```

Класс реализует интерфейс:

```csharp
class Square : IShape
{
    public double Side { get; }
    public Square(double side) => Side = side;
    public double Area() => Side * Side;
}
```

Интерфейсов можно реализовывать **много**:

```csharp
class Bird : IFlyable, IComparable<Bird> { ... }
```

#### Явная реализация

```csharp
interface ILogger
{
    void Log(string message);
}

class ConsoleLogger : ILogger
{
    void ILogger.Log(string message) => Console.WriteLine(message);
}
```

Явная реализация видна только через ссылку на интерфейс. Используется, когда метод не должен быть «на виду» или конфликтует с другим.

### 8. Интерфейс vs абстрактный класс

| Признак | Абстрактный класс | Интерфейс |
|---|---|---|
| Наследование | один | много |
| Состояние (поля) | да | нет (только члены-контракты) |
| Конструкторы | да | нет |
| Когда выбирать | общая реализация + данные | только «что умеет» (контракт) |

**Практическое правило:** если связи «является» (IS-A) и есть общая логика — абстрактный класс. Если нужен только контракт «умеет» (CAN-DO) — интерфейс.

### 9. `is`, `as`, приведение

```csharp
object obj = new Dog();

if (obj is Dog dog)          // pattern matching
{
    dog.Bark();
}

var d = obj as Dog;          // as: null, если тип не подходит
if (d is not null) d.Bark();
```

### 10. IDisposable (анонс)

`IDisposable` — интерфейс с методом `Dispose()`. Его реализуют типы, владеющие ресурсами (файлы, соединения). Подробно разберём в модуле 08.

### 11. LSP — принцип Лисков (интуиция)

Наследник не должен ломать поведение базового класса. Если переопределение бросает исключение там, где базовый класс всегда работает, — иерархия спроектирована плохо. Полноценный разбор — модуль 14.

## Типичные ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Наследование ради переиспользования кода | Хрупкая «родственная» связь ради утилит | композиция (поле вместо наследования) |
| `switch` по типу вместо виртуального метода | Новый тип → правка всех switch | виртуальный метод в базовом классе |
| Забыл `override` / не поставил `virtual` | Метод скрывается, а не переопределяется | планируй иерархию заранее |
| Интерфейс с 15 методами | много реализаций тянет лишнее | дробить интерфейсы (модуль 14) |
| Переопределил `Equals`, забыл `GetHashCode` | коллекции будут вести себя странно | переопределять пару вместе |
